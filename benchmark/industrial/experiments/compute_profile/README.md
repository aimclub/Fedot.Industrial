# Измерение CPU/CUDA для отдельных преобразований

Это воспроизводимый опыт на синтетических тензорах, без обучения моделей и
официального TEST. Он проверяет MTF, дискретизацию и неизменённый GAF как
контрольный случай. Поддержка CUDA этих операций не означает поддержку CUDA
всего графа Industrial.

```powershell
python -m benchmark.industrial.experiments.compute_profile `
    --devices cpu cuda --require-candidate-parity `
    --output-dir .local/compute_profile
```

Для CPU достаточно `--devices cpu`. Явно запрошенная недоступная CUDA приводит
к ошибке, а не к незаметному выполнению на CPU. Настройки опыта находятся в
`defaults.json`; собственный файл передаётся через `--config`.

В `profile.json` сохраняются версии, исходные настройки Torch, контрольные
суммы исходников, отдельные повторы времени, пропускная способность и точность.
`profile.csv` содержит сводные строки. Режим `resident` измеряет операции на уже
размещённых данных; `roundtrip` включает перенос CPU → CUDA, вычисление и возврат
результата на CPU. CUDA синхронизируется при измерении. Пиковая дополнительная
память измеряется счётчиком выделений Torch; это не вся занятая видеопамять.
Пик памяти процесса CPU здесь не измеряется и не подменяется нулём.

Исходные формулы сохранены в `references.py`. Численный эталон MTF вычисляется
в float64: старая интегральная сумма в float32 сама может нарушать допуск.
Отклонения старого алгоритма сохраняются в отчёте, а не скрываются увеличением
допуска. Флаг `--require-candidate-parity` проверяет новый алгоритм после
сохранения доказательств. Допуски опыта не меняют пороги приёмки EVO-04.

`placement.py` дополнительно запускает публичный MTF через
`plan_tensor_operation` и `execute_tensor_operation`. Устройство, последовательный
исполнитель и бюджет памяти заданы независимо и явно. Оценка временной памяти
консервативна, но не ограничивает выделения произвольного вызываемого кода.
Время этой отдельной проверки включает первый вызов и не является оценкой
установившейся производительности. CUDA с Dask/process, несколько GPU и
размещение целых моделей этим примером не подтверждаются.

Измерения зависят от фоновой нагрузки, размера тензоров и стоимости запуска
операций. Сохранённые минимумы, медианы и максимумы нужны для оценки разброса;
один результат нельзя распространять на все задачи. Настройки Torch, параметры
моделей и случайное состояние вызывающего процесса опыт не меняет.
