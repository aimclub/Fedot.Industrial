# Проверка разнообразия мутаций на TRAIN

Это отдельный экспериментальный профиль, не изменение поведения по умолчанию.
Все параметры протокола заданы до обучения в `protocol.json`; параметры моделей,
каталог операций, начальные графы и ограничения берутся из существующего примера.
Планировщик мутаций по умолчанию остаётся выключенным. EVO-04 не пересматривается.

Этап A: до 1000 реальных попыток мутации каждого фиксированного родителя для
ACSF1, Tecator и Airline. Обучение запрещено проверкой вызова `Operation.fit`.
Считаются уникальные топологии, структуры с операциями и полные конфигурации
после подготовки. Это одношаговая выборка, не полное пространство достижимости.
Начальные графы считаются уже известными при проверке новизны. Неизвестный
контекст входа не подменяется выдуманным: запреты советника и валидатора сохраняются.

Обучение разрешено только если B открыл новые допустимые конфигурации относительно
A и начальных графов. Этап B: ACSF1 и Airline, профили A/B, три seed поиска
42/123/2026, итого 12 запусков. A сохраняет текущую стратегию PARAMS, B задаёт
замену 40%, добавление 40%, удаление 20%. Действия без допустимых предложений
не выбираются; фактическая частота зависит от текущего графа. Начальное заполнение
популяции и устранение дубликатов используют прежние вспомогательные стратегии.

Во всех запусках внутренние разбиения и контрольный TRAIN заморожены с seed 42.
Для ACSF1 выделяется стратифицированный контроль 20% официального TRAIN; для Airline
последние 12 месяцев официального TRAIN. Поиск и нормализация его разбиений не
используют контроль. Внутри оставшегося TRAIN — три разбиения. Контроль используется
только после выбора победителя. Официальный TEST не используется вообще.

Каждый поиск получает 300 секунд вместе с подготовкой, один Dask-сеанс с четырьмя
работниками. Параметры моделей и Torch не меняются. Число поколений может отличаться;
недостижение прежней планки 15 поколений не скрывается. Это сравнение качества
при одинаковом верхнем бюджете, не сравнение одинаковой вычислительной работы.
Окончательное обучение на поисковой части TRAIN измеряется отдельно; весь дочерний
процесс ограничен 1200 секундами. Порядок A/B чередуется по seed и задаче заранее.

Основной результат — контрольная потеря TRAIN при одинаковом бюджете. Дополнительно:
новые успешно оценённые конфигурации, отказы, сложность выбранного графа, память,
CPU и динамика внутренней оценки. Три seed недостаточны для статистического
доказательства превосходства. Эти наборы уже применялись при разработке, поэтому
результат нельзя выдавать за независимую окончательную оценку на новых данных.

Новый кэш оценок и отбор предложений по новизне не добавляются. Штатное сохранение
fitness выживших особей GOLEM остаётся прежним. Если разнообразие растёт без
улучшения качества, это не успех. Пороги EVO-04 не меняются ради результата.

Без `--execute` выводится только протокол. Для запусков требуется совместимый
профиль FEDOT, описанный в соседнем примере эволюционного поиска. Результаты и
замороженные исходники сохраняются в новом локальном каталоге `cloud_bundle`;
предыдущие каталоги не перезаписываются. Сырые данные и результаты не добавляются в Git.

## Проверка 28 октября 2026 года

Завершены 20 000 попыток без обучения и все 12 TRAIN-only поисков.
На ACSF1 успешно оценены восемь конфигураций в обоих профилях; на Airline —
четыре в A и семь в B. Контрольное качество совпало, а средний расход CPU
увеличился в B на 8,7% и 19,6% соответственно. Оснований менять исходный профиль нет.

Подробности: `examples/release_1_0/evolution/mutation_diversity_20261028.md`.
Локальные результаты: `examples/artifacts/cloud_bundle/mutation_diversity_20261028/`;
основной отчёт находится в `report_final`, проверка протокола — в
`train_matrix/verification_final.json`. Успешные конфигурации считаются по архиву
принятых оценок, а не по всем успешным возвратам функции оценивания.

Для новой серии используйте новые каталоги, не существующие результаты:

```powershell
python -m benchmark.industrial.experiments.mutation_diversity --output-dir <new-output-dir>
python -m benchmark.industrial.experiments.mutation_diversity --execute --generation-only --output-dir <new-generation-dir>
python -m benchmark.industrial.experiments.mutation_diversity --execute --generation-dir <new-generation-dir> --output-dir <new-matrix-dir>
```

Первая команда только показывает протокол. Для остальных требуется совместимый
профиль FEDOT; использованный локальный профиль и его ограничения описаны в отчёте.
Генерация разрешает обучение лишь при появлении новых полных конфигураций, но
это не гарантирует появления новых топологий или полезных моделей.
