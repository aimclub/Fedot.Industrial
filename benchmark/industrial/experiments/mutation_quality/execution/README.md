# Исполнение замороженного сравнения A/B/C

Этот модуль добавлен отдельно от исходного sealed-пакета. Модели, политики,
сетки, входы и старый исполнитель `run_search` не изменяются. Новый управляющий
модуль закрепляется собственным `launcher_sources.zip` и идентичностью исходников.
Право запуска оформляется отдельно от неизменного `full_series_enabled=false`
в пакете подготовки: разрешение пользователя и явный `--execute` обязательны.

По умолчанию команды только показывают число работ:

```powershell
python -m benchmark.industrial.experiments.mutation_quality.execution --smoke --bundle examples/artifacts/cloud_bundle/mutation_quality_freeze_20261030/frozen_01 --seal eccbefbd7e1cc2b6d0d74188369e13c4145c40c9c8a408606b74333c76930d97
```

Для исполнения добавляются `--execute` и новый `--output-dir`. Допуск `--smoke`
выполняет 15 работ: по одному поколению для каждого источника, зерно 42, варианты
A/B/C чередуются, по пять работ каждого варианта. Бюджеты взяты без сокращения
из замороженного плана: 600 секунд на поиск и подготовку, 90 на кандидата,
1200 на процесс. После одного поколения поиск останавливается раньше предела.
Настройки моделей не меняются.
Результат допуска не используется для подбора параметров или выбора датасетов.

Полная серия запускается режимом `--run --execute`, дополнительно нужен `--gate`
с каталогом успешно завершённого допуска. Перед запуском проверяются все15
квитанций, их артефакты, исходники управляющего модуля и идентичность базового пакета.
Неполный или неуспешный допуск блокирует запуск, без ослабления прежнего допуска
на долю ошибок оценки. Для полной серии применяются только 225 закреплённых работ:
600 секунд поиска, 90 на кандидата, 1200 на процесс, цель 15 поколений.

## Границы данных и окружения

Сырые датасеты не перечитываются. Нормализация и кодирование целей не повторяются:
используются готовые массивы, типы и состояния контейнеров. Все массивы сверяются
с хешами. Поисковый объект не содержит контейнер внешнего контроля. Только после
фиксации выбранной конфигурации полный режим загружает TRAIN-контроль и считает
итоговую оценку. В коротком режиме её нет. Официальный TEST не используется.

Окружение сравнивается после той же инициализации FEDOT, что при заморозке:
`pkg_resources` делает видимыми вложенные служебные дистрибутивы. Это не установка
пакетов и не разрешение игнорировать различия версий. Torch проверяется до работы
и после; настройки не меняются программно. Dask-сеанс принадлежит одному поиску.

## Сохранение и продолжение

Одновременно работает один поиск. `supervisor.lock` не допускает двух владельцев.
`status.json` показывает текущую работу и количество завершённых, `jobs.json`
содержит результаты, `receipts/` — квитанции и хеши артефактов. Статус `incomplete`
означает недостигнутые 15 поколений, не успех по приёмке. Ошибки и тайм-ауты
сохраняются; они не исключаются из будущего анализа.

Повтор той же команды с прежним каталогом проверяет и пропускает завершённые
работы. Их модели не обучаются заново. Это продолжение на уровне целых поисков,
не восстановление оптимизатора из середины поколения. Каталог незавершённой
работы без квитанции требует осмотра; он не перезаписывается автоматически.
После аварии устаревшую блокировку также сначала надо проверить, а не удалять вслепую.

Файл `stop.request` в каталоге серии останавливает её между работами. Принудительно
чужие процессы не завершаются. Внешний ограничитель управляет только потомками
созданного им процесса. Изменение замороженного кода или управляющего модуля
блокирует дальнейшее исполнение; смешивание процедур и автоматический повтор
ошибок контрактов не допускаются.
