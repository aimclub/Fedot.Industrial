# Поэтапный поиск структур и параметров

Новый протокол не меняет предыдущий эксперимент `mutation_diversity` и не
включён по умолчанию. В этом этапе реализованы механизмы и проверки без обучения.
CLI не содержит команды запуска обучающей серии; `training_enabled=false`.

```powershell
python -m benchmark.industrial.experiments.staged_mutations
python -m benchmark.industrial.experiments.staged_mutations --mode fixed
python -m benchmark.industrial.experiments.staged_mutations --audit --output-dir <new-directory>
```

Первые две команды только показывают проверяемую конфигурацию. Третья читает
официальный TRAIN ACSF1/Tecator/Airline через существующий источник данных,
подтверждает тип входа и проверяет составные предложения на настоящем каталоге
операций и валидаторе FEDOT. Обучение запрещено проверкой `Operation.fit`.
Каталог результата должен быть новым, прежние результаты не перезаписываются.
Нужен совместимый профиль FEDOT; в локальной проверке использован прежний
`.local/worktrees/fedot-evo04-ci-smoke` через `PYTHONPATH`.

## Что реализовано

- `RewriteChain`: атомарная замена до трёх последовательных преобразований на
  цепочку из одного–трёх преобразований. При неизменной граничной операции
  сохраняются её идентификатор и параметры, включая горизонт прогноза.
- `ForkFeatureBranch`: целая параллельная цепочка признаков от подтверждённого
  общего входа или существующего входящего ребра. Только классификация и
  регрессия, совместимые табличные выходы, ограничения числа родителей сохранены.
- `PruneFeatureBranch`: удаление целой ветви с сохранением общего префикса и
  остальных входов. Общий выход ветви нельзя удалить.
- `BoundedParameterMutation`: изменение одного параметра только внутри явно
  объявленной сетки. Параметры исполнения, seed, устройство и горизонт защищены.
- `StagedSearchPolicy`: изменение смеси мутаций по потраченному времени,
  ограниченный архив лучших представителей структур и сохранение лучшей оценки.

## Условия будущего сравнения

Режимы `fixed` и `staged` имеют одинаковые операции, начальные графы, сетки
параметров, seed, сроки и долю мест для разных структур (`0.5`). Отличается
расписание вероятностей. В обоих режимах разрешены новые операторы. Это позволяет
проверять расписание отдельно от простого расширения набора мутаций.

Сетка нового протокола: `ridge.alpha`, `logit.C`, `rf.max_depth`.
Канонические начальные значения заданы в `protocol.json`, состав этапов — в
`fedot_ind/core/optimizer/search_policy/defaults.json`. Подготовка
`ParameterSearchPreparation` сохраняет выбранные значения сетки, фиксирует
остальные значения протокола и нормализует `task_type` до вычисления идентичности.
Прежняя подготовка с фиксированными переопределениями не используется для этого
поиска параметров.

Для подключения обучения владелец запуска должен явно собрать задачу, данные,
`ConfirmedObjective.from_training_data(...)`, `ParameterSearchPreparation`
и `IndustrialEvoOptimizer` с конфигурацией `build_config(...)`. CLI этого этапа
намеренно не запускает обучение. Сам по себе параметр `mutation_schedule`
не доказывает, что произвольная сторонняя подготовка графа сохраняет параметры.

## Как читать аудит

`audit.json` содержит начальные графы, планы, результаты проверок, причины отказа,
число топологий и контрольные суммы источника TRAIN. `sources.json` содержит
исходники и их SHA-256. Допустимость графа не означает успешного обучения или
полезности для качества. Искусственная функция оценки используется только в
сквозном модульном тесте и не подменяет оценку моделей на данных.

Предыдущая приёмка EVO-04, настройки Torch и OKHS-FDMD не изменяются.
Новый кэш оценок не добавляется. Полные обучающие серии и выводы о качестве
требуют отдельного следующего этапа.
