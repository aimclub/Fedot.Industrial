# Протокол оценки временных рядов

Этот модуль описывает **что измерять**, но не запускает обучение. Существующие
команды `python -m benchmark.industrial` и манифесты
`benchmark_industrial_manifest@1` не изменены. Новый формат
`benchmark_industrial_protocol@1` старый исполнитель не принимает.

## Границы ответственности

- ROAST владеет типами конфигурации исполнителя: `BenchmarkSuiteConfig`,
  `DatasetSpec`, `ModelSpec`, `MetricSpec`, `RunSpec` и правилами их
  чтения. В поле `suite` передаётся его конфигурация с `schema_version: 1`.
  Зависимость закреплена на [ревизии ROAST 063d579c](https://github.com/data-satanism/ROAST/tree/063d579cc3fa4ef3ea27b59d20f9aaa4ea0e451c).
- Industrial задаёт для каждого `dataset_id` карточку выпуска `release`
  и протокол `protocol`: постановку, доступные входы, разбиение, правила
  предобработки, версии и агрегацию метрик. Модель, её параметры и
  `seed` остаются в `suite`. Лимиты `max_evaluations` и
  `timeout_seconds` задаются в `suite.run.options.evaluation_budget`;
  модуль проверяет и сохраняет лимиты, но не управляет выполнением.
- Этот этап не добавляет поставщиков, загрузчик данных, хранилище и общий
  исполнитель. #303–308 определяют интеграцию с ROAST, #315 определяет
  внешний каталог. Не следует переносить старые результаты в новый
  протокол без доказательств совпадения данных и разбиений.

## Три представления

1. `release` фиксирует выпуск, исходный источник, единицу наблюдения,
   условия доступа, лицензию и SHA-256 одного файла. `artifact` задаётся
   относительно локального корня; файл может быть архивом или снимком
   состава данных с контрольной суммой. `license: null` обозначает
   неизвестные условия, а не разрешение на использование.
2. `protocol` связывает входы, разбиение и правило оценки. Метрики
   перечисляются по идентификаторам уже настроенных метрик ROAST.
   Изменение порядка шагов предобработки существенно; перестановка
   полей JSON и элементов в списках членства не меняет смысл.
3. Разрешённый план содержит `plan_id` полного описания и
   `comparison_key` для условий оценки. В ключ сравнения входят
   выпуск, контрольная сумма, поставщик, разбиение, режим, предобработка,
   конфигурации и версии метрик. Путь локального файла, модель, `seed` и
   бюджет входят в план, но **не** в ключ сравнения. Равенство ключа
   не доказывает сопоставимость бюджета, покрытия или среды выполнения.
   Повторное чтение разрешённого плана проверяет оба идентификатора.

## Разбиения и доступность входов

Поддерживаются `official`, `train_only`, `smoke` и `research`.
Официальный режим требует TEST; внутренний и короткий требуют
валидацию и запрещают TEST. Исследовательский режим сохраняет явно
заданные части, не приравнивая их к официальному протоколу.

Для классификации и регрессии `membership` задаёт непересекающиеся
множества идентификаторов объектов. Если указаны группы, каждый объект
должен иметь группу и группа целиком лежит в одной части.

Для прогноза `temporal` задаёт сетку и окна: ряд, момент прогноза
`origin`, последнюю обучающую точку `fit_end`, горизонт и конечную
точку прогноза `target_end`. Интервал цели имеет вид
`(origin, target_end]`. Допускаются индексы, даты ISO или временные
отметки ISO с часовым поясом; один протокол использует один вид
координат. Для индексов проверяется длина горизонта, для дат и временных
отметок согласование с фактическим календарём остаётся проверкой
адаптера данных. Цель и признаки, доступные только к моменту
прогноза, нельзя объявлять известными на горизонте. Обучаемые
преобразования разрешено настраивать только на TRAIN.

## Предварительная проверка

Из корня рабочей копии, в окружении с установленным дополнением
`benchmark-protocol`:

```console
python -m pip install -e ".[benchmark-protocol]"
python -m benchmark.industrial.protocols benchmark/industrial/examples/protocol_smoke.json
python -m benchmark.industrial.protocols benchmark/industrial/examples/protocol_smoke.json --preflight --data-root ./data
```

Пример описывает условные данные и служит проверкой схемы, не запуском
эксперимента. Без локального файла проверка сообщает `unavailable`.
Другие итоги: `corrupt` при несовпадении SHA-256, `incompatible` при
несовместимом протоколе или пути, `unknown_license` при отсутствии
сведений о лицензии. Несколько причин могут быть возвращены одновременно.
Код выхода: 0 при успехе, 1 при найденных проблемах с наборами, 2 при
ошибке чтения или разрешения манифеста.

Проверка не обращается к удалённому источнику, не распаковывает данные,
не создаёт артефакты и не проверяет права пользователя. Совпадение хеша
доказывает наличие ожидаемых байтов, но не подтверждает корректность
меток или фактическое соответствие записей указанному разбиению.
