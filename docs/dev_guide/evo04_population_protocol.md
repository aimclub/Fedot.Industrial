# EVO-04: протокол сравнения качества и затрат

Протокол зафиксирован до основного обучения. Его числовой источник:
`benchmark/industrial/experiments/mutation_planning/population_study/defaults.json`.
Пороги ниже являются инженерными допусками этой ограниченной проверки,
а не доказанными статистическими границами для любых данных.

## Сравнение

Проверяются девять заранее выбранных исходных наборов:
ECG200, GunPoint, ArrowHead; NaturalGasPricesSentiment, BitcoinSentiment,
BoronConcentration; три ряда M4 Daily с идентификаторами D1, D2, D3.
Для каждого используются начальные значения 42, 123, 777 и два режима мутаций.
Итого 27 пар, 54 отдельных процесса. Наборы не исключаются по результату.
Это приёмочный набор, не полный UCR/TSER/M4 и не утверждение о качестве на них.

Классификация читается из `data`, регрессия из `fedot_ind/data`.
Небольшие одноимённые искусственные файлы из примеров не используются.
M4 читается по явному идентификатору ряда, а не по совпадению номера строки.
Все исходные разбиения сохраняются. Из официальной обучающей выборки отделяется
25% для выбора конвейера; официальная тестовая выборка в поиск не передаётся.
Для M4 последние 14 точек обучающей истории служат проверочными,
официальные 14 будущих значений используются только после окончательного обучения.

В обоих режимах одинаковы текущий `IndustrialEvoOptimizer`, последовательный
исполнитель, каталог операций, исходные графы и начальные значения. Меняется
только `mutation_planning.enabled`. Используются популяции по четыре кандидата
и четыре поколения с учётом начального, то есть три шага эволюции.
Целевой размер популяции четыре; фактический размер сохраняется в отчёте,
но не служит самостоятельным порогом качества и не дополняется копиями графов.
Ограничение поиска 120 секунд, всего отдельного запуска 240 секунд, памяти 8 ГиБ.
Таймер поиска кооперативный: активное обучение может закончиться позже срока.
Превышение записывается отдельно; общий предел 240 секунд контролирует внешний
процесс и при необходимости завершает весь запуск. Это не обещание жёстких
120 секунд на произвольное обучение.
Ошибки и отказы расходуют время; попытки не дополняются до равного числа успехов.
Сравнение ограничено одинаковыми поколениями и таймером, а не равным числом
обучений. `max_candidates` ограничивает перечисление правок одной мутации,
не число оценок моделей. Числа попыток, ошибок и повторно использованных оценок
показываются отдельно и сверяются с диспетчером; расхождение запрещает приёмку.

Классификация и регрессия включают статистические и спектральные признаки,
обычные модели и PDL. Прогнозирование включает `hankelisation -> ridge`,
SSA/MSSA и преобразования ряда; у MSSA явно выбрана линейная голова и CPU.
У статистических генераторов используются глобальные признаки без скользящих
окон: это ограниченная CPU-проверка, а не поиск по всем параметрам генераторов.
OKHS-FDMD не включён, его исходники не меняются.

## Измерения

Каждый запуск получает свежий процесс. CPU ограничен одним потоком в Torch,
BLAS/OpenMP; CUDA скрыта. Фактические пулы потоков сохраняются в результате.
Перед измерением одинаково обучаются и очищаются исходные конвейеры.
Старый кэш вычисленных признаков явно отключён через `use_cache=false`, поскольку
его ключ не учитывает содержимое входов. Параметр должен соблюдаться реализацией,
что проверяется отдельно. Вложенные преобразования Dask работают синхронно.
Порядок двух режимов чередуется по номеру пары, а не по чётности начального значения.

Отдельно измеряются поиск, окончательное обучение на разрешённых данных и
предсказание на тестовой выборке. Память измеряется как RSS процесса и его
потомков с шагом 10 мс, включая нативные выделения, но не как точный непрерывный
максимум и не как память CUDA. Записи сохраняют прогноз, цель, выбранный граф,
события поколений и результаты нативной оценки FEDOT.

До первого запуска сохраняются настройки, полная матрица, подписи исходных
файлов, разбиения и подписи реализаций. Возобновление разрешено только при
совпадении этих данных. Предварительные запуски служат проверкой контура;
их отчёты сохраняются отдельно и не объявляются полной приёмкой.

## Критерии

Потери: `1 - macro-F1`, RMSE, делённая на стандартное отклонение обучающих целей,
и MASE с масштабом среднего абсолютного приращения обучающей истории.
Все масштабы вычисляются без тестовой выборки. Сырые метрики разных задач
не усредняются между собой.

Для каждого набора среднее ухудшение по трём начальным значениям не превышает
0,03 / 0,05 / 0,10 соответственно. На отдельном начальном значении пределы
0,10 / 0,15 / 0,30. Допуски отделяют небольшую вариативность поиска от явно
неприемлемого ухудшения; три повторения не являются статистическим доказательством.
Чтобы сравнение не свелось к одинаково плохим моделям, для каждой задачи хотя бы
один набор в обоих режимах должен в среднем улучшать простой ориентир на 0,02:
частый класс, медиану обучающих целей или последнее значение ряда.

В каждой паре затраты нового способа не превышают:

| Этап | Ограничение относительно прежнего способа |
|---|---|
| Поиск | `1,25 * время + 2 с` |
| Окончательное обучение | `1,50 * время + 1 с` |
| Предсказание | `1,50 * время + 0,05 с` |
| Максимальный RSS | `1,25 * память + 128 МиБ` |

Абсолютные добавки учитывают запуск коротких операций и шум измерений.
Их доля в фактическом результате должна быть показана: прохождение только
благодаря этим добавкам не доказывает ускорение. Ускорение вообще не является
заранее обещанным результатом.

Нужны все 54 исхода, оценка всех членов фактических популяций и хотя бы одна новая успешная оценка
в каждом из трёх шагов эволюции. Доля ошибок оценки в отдельном запуске не выше
10%; все ошибки остаются в отчёте. Повторное использование качества само по
себе не доказывает прохождение поколения. Ошибка запуска, несовпадение данных,
отсутствующее измерение или неполный эксперимент не могут дать статус приёмки.

Число уникальных графов остаётся диагностикой. Порог 120/120 из структурного
сравнения не подменяет проверку качества и затрат. EVO-04 закрывается только
после проверки итогов, без изменения этих допусков по увиденным результатам.

В предварительной проверке исправлены неверное имя спектральной операции,
упаковка нативных классификаторов в FEDOT, явное отключение старого кэша и
различие между числом шагов GOLEM и числом снимков с начальной популяцией.
Три шага после начального состояния соответствуют `num_of_generations=3` GOLEM.
Промежуточный фактический размер популяции может уменьшаться, что само по себе
не является дефектом и согласуется с отказом от критерия количества графов.
Числовые допуски качества и затрат при этих исправлениях не менялись.
Стандартные скользящие окна существенно увеличивали стоимость предварительной
серии. До основного сравнения для обоих режимов
зафиксированы глобальные признаки. Предварительные попытки не входят в итоговую
матрицу и не используются для выбора модели по тестовой метрике.
