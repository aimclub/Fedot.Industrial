# EVO-06: явный исполнитель Dask

## Изменение поведения

Dask выбирается через `EvolutionConfig.evaluation_execution.backend="dask"`.
Новый `DaskEvaluationDispatcher` использует те же подготовку графа, подписи
конфигураций, архив завершённых оценок и преобразование ошибок, что и локальный
исполнитель EVO-05. Исполнитель не запускается при импорте модуля.

`FedotIndustrial` больше не создаёт Dask-клиент при каждом запуске решателя.
Из `IndustrialDispatcher` удалены `delayed` и `dask.compute`.
Значение настройки по умолчанию осталось `legacy`, но этот совместимый путь
теперь последовательный: прежнего неявного параллелизма через внешний Dask
нет. Для параллельной оценки нужно явно выбрать `process` или `dask`.
Ручной сервис `DaskRuntimeInitializer.start` сохранён для существующих
пользователей, однако решатель его автоматически не вызывает.

## Конфигурация

```python
from fedot_ind.core.optimizer.configuration import EvolutionConfig
from fedot_ind.core.optimizer.evaluation.configuration import (
    EvaluationBackend, EvaluationExecutionConfig,
)
from fedot_ind.core.optimizer.evaluation.dask_config import DaskExecutionConfig

policy = EvolutionConfig(
    random_seed=42,
    evaluation_execution=EvaluationExecutionConfig(
        backend=EvaluationBackend.DASK,
        candidate_timeout_seconds=120,
        total_timeout_seconds=600,
        dask=DaskExecutionConfig(
            retries=0,
            startup_timeout_seconds=60,
            restart_timeout_seconds=30,
            memory_limit=2 * 1024**3,
        ),
    ),
)
```

Эта конфигурация передаётся в существующее поле стратегии оптимизации
через `policy.to_record()`. Размер группы рабочих процессов определяется
`requirements.n_jobs`. Один процесс выполняет не более одного кандидата
одновременно; число потоков выполнения заданий Dask в нём равно одному.
Это не ограничивает автоматически внутренние потоки сторонней модели.

В JSON параметр `memory_limit` принимает `"auto"` либо положительное целое
число байтов на рабочий процесс. В режиме `"auto"` доступная Dask память
делится на запрошенное число процессов. Это настройка контроля памяти Dask,
а не доказанный жёсткий предел памяти для произвольной модели.
Неизвестные поля, строки вместо чисел, логические значения вместо чисел,
неконечные интервалы и настройки Dask для другого исполнителя отклоняются.
Старые записи конфигурации без секции `dask` не меняют своё представление.

## Владение ресурсами

- На одну группу оценок создаются собственные `LocalCluster` и `Client`.
  Они не используют и не закрывают существующий клиент пользователя.
- Клиент не становится клиентом по умолчанию. Сетевые службы ограничены
  адресом `127.0.0.1`; для служебного HTTP используется свободный порт.
- Координатор доставляет описание каталога расширений. Каждый рабочий процесс
  сравнивает его подпись со своим установленным каталогом до первого задания.
  При восстановлении процесса проверка выполняется повторно.
- Реестр расширений активируется в области одного вызова оценки графа.
  Повторная настройка всего Industrial внутри задания не выполняется.
- Проверяется наличие Nanny, одного потока выполнения задания и положительного
  бюджета памяти. Без подтверждённого рабочего процесса кандидат не запускается.
- При обычном завершении, отмене и ошибке предпринимается закрытие как клиента,
  так и кластера. Если закрытие подтвердить нельзя, возникает `DaskCleanupError`:
  продолжать оптимизацию как после успешной очистки нельзя.

## Ошибки, повторы и время

План `DaskEvaluationPlan` содержит только данные, не клиент и не живой граф.
Результаты возвращаются в порядке плана, а не завершения процессов.
Один кандидат получает один окончательный `ExecutionResult` и одну запись
в общей диагностике и архиве. Отдельные попытки доступны в
`DaskEvaluationDispatcher.last_dask_attempts` и не считаются новыми кандидатами.

Автоматические повторы заданий Dask и перезапуски потерянного задания
планировщиком отключены. Координатор может явно повторить только потерю рабочего
процесса или связи. `retries` задаёт от нуля до трёх дополнительных попыток;
по умолчанию их нет. Ошибка модели, недопустимое качество и ошибка сериализации
результата не являются поводом повторять обучение.

Полный результат атомарно сохраняется в отдельном временном каталоге группы;
Dask передаёт только короткое подтверждение. Координатор читает результат
непосредственно из этого каталога, не ожидая восстановления потерянного
значения через `Future.result()`. Если Dask повторно вычисляет потерянное
подтверждение, уже сохранённая оценка читается без повторного обучения.
Каталог удаляется после закрытия рабочих процессов. Поэтому этот вариант
предназначен именно для локального кластера с общей файловой системой.
Ошибка сериализации входа относится только к соответствующему кандидату
и не отменяет отправленные исправные задания.

Общий предел времени включает создание кластера и подготовку процессов.
Предел кандидата начинается при первой отправке и не сбрасывается при повторе.
Время проверяется повторно после получения результата: запоздавшая успешная
оценка не принимается. При превышении предела отдельного кандидата его рабочий
процесс принудительно перезапускается через Nanny. Одной отмены `Future`
для остановки работающего `fit` недостаточно.

Эти пределы относятся к заданиям, переданным исполнителю. Предварительное
обучение исходного предположения в FEDOT выполняется до оптимизатора и в
`DaskEvaluationPlan` не входит. Общий предел всего `FedotIndustrial.fit`
этой доработкой не обеспечивается. Этот отдельный этап нельзя считать
прерванным только потому, что задан предел оценки кандидата.

При общей отмене или исчерпании времени незавершённые результаты помечаются
соответствующим состоянием, после чего закрывается принадлежащий исполнителю
кластер. Уже завершённые результаты не заменяются поздними сообщениями.
Падение одного кандидата не отменяет успешные результаты остальных.

## Проверки и границы выводов

Проверки используют синтетические данные и закреплённую совместимую копию
FEDOT. Новое обучение на бенчмарках и подбор по официальному TEST не проводились.
Параметры моделей, настройки Torch, OKHS-FDMD и пороги EVO-04 не менялись.
Отрицательная приёмка EVO-04 сохраняется, планировщик мутаций по умолчанию
не включается. Измерений ускорения Dask эта доработка не содержит.

Проверяются сопоставимость с последовательным исполнением при заданных seed,
порядок результатов, отказ модели без повторов, принудительное падение процесса,
ограниченный повтор, отмена работающего обучения, отсутствие оставшегося процесса,
ошибка получения результата и отказ при неподтверждённой очистке.

Для настоящего оценщика FEDOT проверены классификация, регрессия и
прогнозирование на двух разбиениях: предсказания сопоставляются с независимыми
повторными обучениями. Ошибка второго разбиения не допускает частичную оценку.
Отдельная проверка проходит через `FedotIndustrial.fit/predict`.

Сетевой доступ к чужому планировщику, общий кластер с посторонними заданиями,
CUDA-распределение и ограничения внутренних потоков модели в эту итерацию
не входят. Политика CPU/CUDA и стоимость передачи данных относятся к EVO-07.
Копирование графов и данных, а также новый кластер на каждую группу имеют
дополнительную стоимость, которую следует измерить до изменения настроек
по умолчанию. Функции оценки должны быть пригодны к явному повтору:
единственная итоговая запись не означает однократность внешних побочных
эффектов обучения при падении процесса.

## Ограничение общего прогона

Четыре старых параметризованных сценария
`tests/unit/api/main/test_api_main.py::test_fit_predict_fedot_industrial`
исключены из окончательного целевого прогона. Профилирование принадлежащего
нам процесса показало длительное обучение RandomForest внутри PDL на этапе
проверки исходного предположения FEDOT, до запуска оптимизатора. Полный
прогон был остановлен, а не объявлен успешным. Параметры моделей и размеры
данных этих тестов не менялись.

Исключение не относится к новым проверкам EVO-06: публичный Dask-путь
`FedotIndustrial.fit/predict`, три задачи на настоящих разбиениях FEDOT,
локальные исполнители и сценарии восстановления проверяются отдельно
на явно ограниченных синтетических данных.
