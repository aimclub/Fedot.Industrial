# EVO-07: устройства вычислений, память и стоимость передачи данных

Дата проверки: 26 октября 2026 года. Задача: [EVO-07, #291](https://github.com/aimclub/Fedot.Industrial/issues/291).
Изменения подготовлены в `industrial_release_1.0`, не в `main`.

## Что изменено

Добавлен пакет `fedot_ind.core.optimizer.compute` с отдельными описаниями
устройства, способа исполнения, входного и выходного тензоров, возможностей
операции и бюджета памяти. Планирование не импортирует Torch и Dask, не создаёт
клиентов и не переносит данные. Результат — неизменяемый `TensorOperationPlan`
либо `ComputeRejection` с явной причиной отказа.

`execute_tensor_operation` проверяет фактический тензор и исполняет одну
операцию. Перенос выполняется явно, а CUDA синхронизируется только при измерении.
Автоматический выбор устройства и незаметный переход на CPU не допускаются.
Интерпретатор поддерживает последовательное исполнение; CUDA с `process` или
`dask` отклоняется до запуска. Это не распределитель GPU для целых моделей.

Из каталога расширений и адаптера графов удалён вывод «Torch означает CUDA».
По умолчанию объявляется только CPU. Поддержка CUDA требует явного `devices`;
неизвестные, пустые и повторяющиеся объявления проверяются отдельно.

После исходного профилирования переработаны две дорогие операции:

1. MTF при уменьшении временной оси использует частоты состояний в окнах:
   `H @ P @ H.T`. Вместо разворачивания `B × T × T` строятся префиксные
   гистограммы `B × T × K`, где `K` — число дискретных состояний. Границы окон,
   перекрытие и порядок осей сохраняются. Для отсутствия уменьшения и больших
   `K` оставлен прямой путь.
2. Дискретизация использует поиск границ без временного тензора сравнений
   `B × T × K`. Сортировка сохраняет смысл подсчёта строго меньших границ,
   включая повторы, неупорядоченные значения, NaN-паддинг и бесконечности.
   Для CUDA при числе границ до семи оставлен прежний алгоритм: на проверенных
   малых случаях он быстрее. Порог хранится в соседнем `kernel_defaults.json`,
   который включён в wheel и исходный архив.

GAF измерен как контрольный случай и не оптимизировался. Третью операцию
не меняли без подтверждённой необходимости. Параметры моделей и публичные
настройки преобразований не изменены.

## Протокол и источники

Воспроизводимая команда:

```powershell
python -m benchmark.industrial.experiments.compute_profile `
    --devices cpu cuda --require-candidate-parity `
    --output-dir .local/evo07_profile
```

Профилировщик находится в
`benchmark/industrial/experiments/compute_profile`; размеры, seed, число
повторов, допуски и бюджет — в `defaults.json`. Исходные формулы сохранены
отдельно от нового выбора алгоритмов в `references.py`.

Проверены семь сочетаний размеров: дискретизация с 8/64 состояниями, MTF с
делимой и неделимой длиной ряда, MTF без уменьшения и GAF. Для каждого случая
есть CPU/CUDA, исходный/новый алгоритм и два режима: данные уже на устройстве
и полный перенос CPU → CUDA → CPU. Два прогрева, семь измерений; время CUDA
измеряется с ожиданием завершения. Сохраняются отдельные повторы, минимум,
медиана, максимум, пропускная способность, число переданных байтов и точность.

Артефакты этой проверки:

- [profile.json](evo07_profile_20261026/profile.json): настройки, версии,
  контрольные суммы исходников, повторы и проверка размещения MTF;
- [profile.csv](evo07_profile_20261026/profile.csv): сводные измерения.

Поле `revision` указывает базовый HEAD до коммита этой доработки. Фактически
измеренные файлы рабочей копии определяются по `source_sha256`, а не только
по этому HEAD.

Среда: Windows, Python 3.10, Torch 2.6.0+cu126, RTX 4080 16 ГБ, драйвер 571.96.
CPU и CUDA сравниваются в одном процессе и одной сборке Torch. CUDA-сборка
установлена отдельно в `.local/evo07-cuda-torch-2.6`; исходное проверочное
окружение `.local/evo04-cpu-20261019` сохранило Torch 2.6.0+cpu.

Число потоков и параметры точности Torch не менялись; значения записаны в JSON.
Фоновая нагрузка не контролировалась: перед итоговым измерением GPU был занят на 5%.
Чужие процессы не останавливались. Даже неизменённый контрольный GAF показывает
заметный разброс времени. Поэтому приведённые отношения — наблюдения этого
опыта, а не обещание ускорения всего обучения.

## Результаты

Медианное время операций на уже размещённых данных, миллисекунды:

| Операция и размер | Устройство | Исходный алгоритм | Новый алгоритм |
|---|---|---:|---:|
| Дискретизация, B=64, T=2048, K=8 | CPU | 0,609 | 0,297 |
| Дискретизация, B=64, T=2048, K=64 | CPU | 10,279 | 0,373 |
| Дискретизация, B=64, T=2048, K=64 | CUDA | 0,247 | 0,265 |
| MTF, B=8, T=1024, S=64, K=8 | CPU | 7,129 | 0,384 |
| MTF, B=8, T=1024, S=64, K=8 | CUDA | 0,913 | 0,399 |
| MTF, B=8, T=1023, S=64, K=8 | CPU | 26,325 | 0,352 |
| MTF, B=8, T=1023, S=64, K=8 | CUDA | 1,450 | 0,426 |

На малой дискретизации CPU ускорение не подтверждено. На CUDA с 64 состояниями
новый поиск медленнее, но дополнительная пиковая память Torch уменьшилась
с **72,875 до 3,141 МиБ**. Это осознанный обмен времени на память, а не ускорение
CUDA. При малом числе границ сохранён исходный путь.

Для двух MTF с S=64 дополнительный пик CUDA уменьшился с **224 до примерно
0,751 МиБ**. Измеряется память выделений Torch сверх уже размещённых входов;
память драйвера, сторонних процессов и весь объём видеопамяти сюда не входят.
Пик памяти процесса CPU не измерялся. Пустые значения CSV не означают ноль.

Для неделимой длины старый интегральный алгоритм float32 сам нарушает допуск
`rtol=atol=1e-5` относительно исходной формулы float64. Эти отрицательные
результаты сохранены. Новый алгоритм проходит тот же допуск на CPU и CUDA;
дискретизация совпадает точно. Допуски опыта не заменяют пороги EVO-04.

Отдельно публичный MTF выполнен через план устройства и памяти. Для входа
8×1024 float32 перенос CPU → CUDA составляет 32768 байт, результат остаётся
на выбранном устройстве. Оценка памяти CUDA — 3448832 байта при заданном бюджете
512 МиБ на устройство. Это проверка учёта входа, выхода и объявленной временной
памяти, а не жёсткий ограничитель выделений. Первый вызов с инициализацией
не используется для утверждений о производительности.

## Проверки

- CPU: **432 теста прошли, 32 пропущены**; CUDA-проверки недоступны в CPU-сборке,
  десять сравнений требуют необязательную библиотеку `pyts`.
- Реальная CUDA: **230 тестов прошли, 10 пропущены** из-за отсутствия `pyts`.
  Проверяются точность, формы, NaN/бесконечности, перекрытия, пакетная обработка,
  сохранность входов, градиент по матрице переходов и публичный вызов MTF.
- Свойства дискретизации проверяются генерируемыми примерами Hypothesis.
  Планирование проверяется на типы, переносимость, бюджеты и недопустимые
  сочетания устройства и исполнителя; среда Torch не меняется.
- Wheel собран из исходного архива. Состав обоих архивов проверен;
  отдельная установка вне рабочей копии загрузила JSON и выполнила MTF через
  публичный план. Это не чистая установка всех ML-зависимостей.
- Независимое ревью выявило пропуск квадратичных буферов матрицы переходов
  в оценке памяти примера MTF. Расчёт исправлен; граничный тест подтверждает
  отказ до вычисления при большом числе состояний и недостаточном бюджете.

## Границы приёмки

Подтверждён последовательный путь отдельных тензорных операций, а не CUDA
всех генераторов, нейросетей, моделей или эволюционных графов. Dask/process CUDA,
несколько GPU и жёсткое ограничение памяти произвольного вызываемого кода
остаются вне этой реализации. Полный прогон всех тестов репозитория не выполнялся.

Обучение на бенчмарках не запускалось, официальный TEST не использовался.
Параметры моделей, настройки Torch, OKHS-FDMD и пороги приёмки не менялись.
Отрицательная приёмка EVO-04 сохраняется. Коммит не закрывает GitHub issue
автоматически и не означает разрешения на слияние в `main`.
