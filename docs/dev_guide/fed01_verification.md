# FED-01: подготовка данных перед интеграцией Industrial и FEDOT

> Исторический отчёт. Действующий контракт после завершения перехода описан в
> `ind_fedot_05_verification.md` и `platform_support.md`.

## Статус и размещение

Результаты FED-01 вошли в общий цикл FED-01–03, собранный в Pull Request
[`aimclub/FEDOT#1462`](https://github.com/aimclub/FEDOT/pull/1462). Зафиксированная
для интеграции версия всего цикла:
`d1875e7a1ba49c94d13c51d97ec78829bf459ca8`.

| Репозиторий | Ветка и назначение |
|---|---|
| Industrial | `industrial_release_1.0`: отчёт и последующая граница совместимости INT-01. |
| FEDOT | Pull Request #1462 в целевую ветку `refactor/fedot_1.0.0`. |

Исходной основой FED-01 был коммит
`5a55f7e13a4a0f325953632ca9a87116ddecd3ec`.
Реализация контрактов алгоритмического ядра не копировалась в Industrial.

## Было и стало

| Область | Было | Стало |
|---|---|---|
| Индексы объектов | Создание `idx` могло опираться на ширину признаков. | Одна метка по оси объектов; удаление строк сохраняет исходные метки. |
| Пропуски цели | Многомерные маски могли менять смысл индексации. | Проверка целевого значения по объекту, одна маска для признаков, цели и индексов. |
| Временные ряды | Преобразование могло смешивать временную ось и каналы. | Явные формы `(samples, time)` и `(samples, channels, time)`, горизонт по последней оси. |
| Подготовка при предсказании | Зависимость от планов и моделей в трассировке. | Схема и снимки уже обученных преобразований принадлежат тренировочным данным. |
| Кодирование классов | Даже новое предсказание восстанавливало метки через файлы кэша. | Для новых контейнеров используется состояние в памяти; старый путь по трассировке сохранён. |
| Связь столбцов | После удаления цели или кодирования имена и позиции могли расходиться. | Подготовленные имена, исходная схема, сохранённое отображение столбцов и его композиция при необязательной подготовке. |
| Исходные данные | Массивы и настройки могли попадать в изменяемый рабочий объект по ссылке. | `create_data` владеет результатом; исходные массивы, настройки и тренировочный контейнер не меняются. |
| Преобразование через `InputData` | Вложенный `Task` передавался по ссылке. | Массивы и изменяемые метаданные копируются; неподдерживаемая временная индексация отклоняется явно. |
| Устройство | Создание данных могло менять глобальный backend. | Временное переключение восстанавливается, устройство определяется по тензорам. |
| Ошибка перемещения | Часть полей могла измениться до сбоя `.to()`. | Поля заменяются только после успешного перемещения всех тензоров. |
| Python 3.11 | Импорт `DataSpec` блокировался изменяемым значением `Task` по умолчанию. | `default_factory` и частные копии изменяемых настроек. |
| Установка | `pyproject.toml` не объявлял все зависимости публичного API. | Добавлены `pymonad`, `python-dotenv` и зависимость снимков `cloudpickle`. |

Новый контейнер не создавался. Проверки и схемы находятся рядом с
`fedot/core/data/tensor_data`, преобразования совместимости в
`fedot/core/data/bridges`, выбор столбцов в тематическом пакете планирования.
Чтение, обучение обработчиков и кэширование выполняет тонкий исполнитель
`TensorDataCreator`, использующий существующие алгоритмы подготовки.

## Доказательства

| Проверка | Результат |
|---|---|
| Исходный набор на Python 3.10 | 221 passed, 3 failed, 2 skipped, 27 deselected. |
| Итоговый расширенный набор на Python 3.10.0 | 491 passed, 5 skipped, 1 deselected; 56,91 с. |
| Тот же итоговый набор на Python 3.11.5 | 491 passed, 5 skipped, 1 deselected; 57,90 с. |
| Обучение `torch_linear` через `Fedot.fit` | Входит в итоговый набор; настоящая CPU-модель, числовые и строковые классы. |
| Повторные `Fedot.predict` | Совпадающие предсказания; входные данные и состояние подготовки не меняются. |
| Запрет загрузки состояния из файлов при предсказании | Входит в итоговый набор; запрет контролируется отдельно от флага `use_cache`. |
| Независимые проверки свойств | Сохранение масок и значений, восстановление столбцов, разбиение на пакеты, неизвестные категории, преобразования через `InputData`, временные оси. |
| Отсутствие копирования при `.validate()` | Адресный тест запрещает `torch.Tensor.clone` после создания контейнера. |
| Компиляция изменённых Python-файлов | 29 файлов на обоих Python, без ошибок. |
| Совместимость установленных пакетов | 151 пакет на Python 3.10 и 150 на Python 3.11, противоречий нет. |
| Форматирование и пробельные ошибки | Повторный `autopep8 --diff` пустой; `git diff --check` без ошибок. |

Три исходных падения относятся к устаревшим ожиданиям тестов:
нормализация `cuda`, тип ошибки неизвестного backend и удалённый частный
метод `Operation`. Они заменены проверками актуального публичного поведения.
Новые правила выявили некорректные фикстуры с несогласованным числом объектов;
фикстуры исправлены, требования к согласованности не ослаблены.

Независимый проверяющий обнаружил передачу `Task` по ссылке. Дополнительная
проверка настоящей модели обнаружила скрытую загрузку декодера с диска.
Оба дефекта исправлены и защищены тестами без `xfail`.

## Окружение и команды

Проверки выполнялись в отдельных окружениях Python 3.10.0 и Python 3.11.5.

Используются PyTorch `2.5.1+cpu`, NumPy `1.26.4`, SciPy `1.12.0`,
pandas `2.2.3`, scikit-learn `1.3.2`, sktime `0.30.1`,
Dask/distributed `2024.4.2`, dask-ml `2024.4.4`.
Редактируемая установка FEDOT указывает на рабочую копию для ревью.
Окружения проверены через `uv pip check`.

Выполнять из корня рабочей копии FEDOT, подставив нужный интерпретатор:

```powershell
python -m pytest tests/api/test_create_data.py tests/api/test_create_data_contract.py tests/api/test_create_data_invariants.py tests/api/test_fed01_model_smoke.py tests/core/data tests/core/backend tests/preprocessing tests/core/caching tests/core/operations/test_operation_tensordata_contract.py tests/core/pipelines/test_pipeline.py tests/core/pipelines/test_pipeline_rules.py --deselect=tests/core/data/test_tensor_data_cpu.py::test_loader -q -rs
```

Локальные журналы предыдущих прогонов не входят в репозиторий. Итоговые числа
и существенные ограничения приведены в этом отчёте.

## Что не доказано

- Это адресная проверка FED-01 в Windows, не полный набор FEDOT/Industrial,
  не проверка Linux и не подтверждение Python 3.12–3.14.
- PyTorch CPU установлен явно. Базовая установка FEDOT без PyTorch
  не считается проверенной; политика необязательных зависимостей не менялась.
- Пять пропусков: два GPU-модуля без `cupy`, одна проверка сохранения без CUDA
  и две проверки transformer-признаков без `sentence-transformers`.
- Сетевой UCR-тест явно исключён. Он прошёл в расширенном прогоне Python 3.10;
  одновременный прогон Python 3.11 столкнулся с общей временной папкой.
  Тест исправлен на собственный `tmp_path`, но повторная проверка загрузки
  через сеть в окончательный набор не входит.
- Настоящее обучение проверено на `torch_linear` для классификации.
  Регрессионные и прогнозные данные проверяются через создание, маски и схемы;
  все модели, преобразования расширений и задачи обучения здесь не проверялись.
- `use_cache=False` сохраняет существующие записи плана и обработчиков
  для старого пути по `trace_uuid`. Доказано отсутствие их чтения новым путём
  при предсказании, а не полное отсутствие записи на диск.
- Старый `InputData` с одномерным временным рядом и индексами моментов времени
  явно отклоняется с `temporal_index_bridge`; метаданные не теряются молча.
- Трассировка без исторической схемы не даёт полного доказательства порядка
  столбцов. Для нового кода рекомендуем `from_data=train`.
- Плоский завершающий прогноз по горизонту остаётся старым выходным режимом.
  Полный контракт выходов моделей и преобразований относится к FED-02.
- Прямой конструктор `TensorData` заимствует хранилище признаков/цели;
  отложенный вызов заимствует источник до первого `get()`. Это явно описанные
  границы владения, не гарантия копирования каждого переданного объекта.
- `cloudpickle` используется только для доверенных снимков обучения;
  произвольные внешние файлы нельзя считать безопасными или переносимыми
  между несогласованными версиями окружения.

## Связь с интеграцией

INT-01 проверяет общий результат FED-01–03 по точному SHA в отдельном профиле
`fedot-tensor`. Профиль не становится основным до вливания Pull Request #1462
и переноса ключевых сценариев Industrial.

Естественный объём FED-01 составляет примерно 2,5 тыс. изменённых строк кода
и тестов, то есть меньше предварительного бюджета 3,2–4,5 тыс. строк.
Изменения не дополнялись переносами, переименованиями или проверками других
подсистем ради достижения численного порога.
