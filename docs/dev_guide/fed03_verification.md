# FED-03: проверка полного и воспроизводимого оценивания

> Исторический отчёт. Действующий контракт после завершения перехода описан в
> `ind_fedot_05_verification.md` и `platform_support.md`.

## Назначение

Этап FED-03 завершает цикл FED-01–03 в Pull Request
[`aimclub/FEDOT#1462`](https://github.com/aimclub/FEDOT/pull/1462). Реализация
подготовлена в ветке `codex/industrial-fed02-review` поверх
`origin/refactor/fedot_1.0.0`. Изменения Industrial в этот Pull Request не входят.

Цель этапа — исключить частично рассчитанные метрики и скрытые повторные запуски,
сделать границы кэша явными и предоставить проверяемые точки подключения для
оценивания, проверки кандидатов и воспроизводства популяции.

## Реализованный контракт

| Область | Гарантия |
|---|---|
| Результат оценивания | `EvaluationComplete` создаётся только для полного набора разбиений; `EvaluationIncomplete` не содержит усреднённой метрики. |
| Повторные попытки | `RetryPolicy` ограничивает число попыток; повтор разрешён только для явно отмеченных временных ошибок. |
| Освобождение состояния | Каждая начатая попытка освобождает состояние в `finally`; ошибка очистки не скрывает журнал предыдущей ошибки. |
| Повтор кандидата | Завершённый результат используется повторно только при совпадении кандидата, данных и настроек оценивания. |
| Кэш TensorData | Ключ учитывает содержимое данных, состояние подготовки, разбиение, кандидата, устройство и пространство имён. |
| Кэш предсказаний | Записи попытки сначала изолированы в `PredictionCacheSession` и публикуются только после успеха. |
| Ограничение времени | Обучение выполняется на копии графа; позднее завершение не меняет исходный граф и не публикует предсказание в общий кэш. |
| Уникальность популяции | Структурные дубли устраняются до оценки; уже оценённый экземпляр имеет преимущество независимо от порядка. |
| Воспроизводство | `BoundedReproduction` ограничивает число попыток и использует детерминированный план случайных состояний. |
| Интеграция с GOLEM | Используются открытые атрибуты `eval_dispatcher` и `reproducer`; исходный код GOLEM не изменён. |

Публичные настройки собраны в `EvolutionHooks` и подключаются через
`ComposerBuilder.with_evolution_hooks`. Существующие точки входа `Pipeline` и
`PipelineObjectiveEvaluateWithTensorData.evaluate` сохранены.

## Независимая проверка

После основной реализации отдельный проверяющий добавил инвариантные проверки
контрактов оценивания, кэша и популяции. Они выявили ошибку выбора дубликата:
если неоценённый экземпляр находился раньше уже оценённого, диспетчер мог сохранить
первый и потерять готовый результат. Алгоритм исправлен: оценённый экземпляр теперь
имеет преимущество, но логический порядок уникальных кандидатов остаётся устойчивым.

Дополнительно проверено, что рабочий процесс, завершившийся после ограничения
времени, не может записать предсказание в общий кэш. Для этого обучение получает
локальную сессию кэша, которая закрывается вместе с рабочей копией графа.

## Результаты проверок

Основной адресный набор на Python 3.11:

```text
353 passed, 2 skipped
```

Он включает `tests/extensions`, проверки оценивания, популяции, кэша,
ограниченного по времени обучения и сборщика композитных моделей. Два пропуска
относятся к существующим проверкам кэширования.

Расширенный набор `tests` без устаревшего `tests/industrial`:

```text
1131 passed, 12 failed, 6 skipped
```

Все 12 ошибок воспроизводились до FED-03. Они относятся к незавершённой миграции
на `TensorData`, устаревшим тестовым подменам API, прежним ожиданиям настроек и
сетевой проверке загрузчика UCR. Новых ошибок, вызванных FED-03, в этом наборе нет.

Локальное окружение Python 3.10.0 дало:

```text
333 passed, 12 failed, 2 skipped
```

Все 12 ошибок возникают внутри Hypothesis до вызова кода FEDOT:
`TreeNode` не получает поле `is_exhausted` из-за ошибки
`dataclasses(slots=True)` в Python 3.10.0. Эта ошибка исправлена в последующих
выпусках Python 3.10; проверка ветки должна использовать актуальный исправляющий
выпуск. На Python 3.11 те же проверки проходят.

Компиляция изменённых модулей, `git diff --check` и адресная проверка оформления
проходят. В документации Read the Docs исправлена неверная длина подчёркивания
заголовка `Sampling Stage Before AutoML Search`, из-за которой прежняя сборка
Pull Request завершалась ошибкой.

## Ограничения

- `func_timeout` ограничивает ожидание потока, но не может немедленно остановить
  нативный код. Изоляция защищает исходный граф и общий кэш, однако вычисления
  могут продолжаться до возврата управления библиотекой.
- Публикация нескольких файлов дискового кэша не является общей транзакцией.
  При ошибке ввода-вывода отдельные совместимые записи могут сохраниться.
- Воспроизводимость распространяется на план отбора, скрещивания и мутации.
  Она не гарантирует побитово одинаковый результат CUDA или сторонних операций
  с собственными источниками случайности.
- Полный набор старых тестов FEDOT ещё содержит долги миграции. Их следует
  устранять отдельно, не ослабляя контракт FED-03.
- Выполнение на GPU, распределённый исполнитель и жёсткое прекращение процесса
  не входят в этот этап.

## Команда проверки

Выполнять из корня рабочей копии FEDOT в окружении с дополнительной группой
зависимостей `test` и установленным PyTorch:

```powershell
python -m pytest tests/extensions tests/core/optimisers tests/core/caching tests/core/pipelines/test_timed_fit_ownership.py tests/core/pipelines/tuning/test_tuner_builder.py -q
```

## Готовность цикла FED

FED-01 закрепил владение и подготовку `TensorData`. FED-02 добавил проверяемый
контракт внешних моделей и преобразований. FED-03 сделал оценивание полным,
ограниченным и наблюдаемым. Вместе эти этапы образуют основу для последующей
интеграции Industrial: данные, внешние операции и эволюционное оценивание имеют
явные границы и адресные проверки.

INT-01 уже проверяет точный снимок Pull Request #1462 в отдельном профиле
`fedot-tensor`. До вливания этого Pull Request и переноса ключевых сценариев
Industrial профиль остаётся экспериментальным и не заменяет `fedot-legacy`.
