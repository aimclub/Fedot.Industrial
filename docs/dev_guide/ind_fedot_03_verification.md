# IND-FEDOT-03: выполнение Industrial-моделей через TensorData

> Исторический отчёт промежуточного этапа. Итоговый контракт описан в
> `ind_fedot_05_verification.md`.

Дата проверки: 22 сентября 2026 года.

## Назначение

Этап `IND-FEDOT-03` переносит основные сценарии классификации и регрессии на
границу данных FEDOT 1.0. Работа выполнена после вливания Pull Request
[`aimclub/FEDOT#1462`](https://github.com/aimclub/FEDOT/pull/1462) и проверена
на снимке `d1875e7a1ba49c94d13c51d97ec78829bf459ca8` ветки
`refactor/fedot_1.0.0`.

Цель этапа — дать PDL и Kernel Learning единый путь `fit` → `predict` через
настоящий `TensorData`, сохранив явные схемы данных, индексы образцов и
типизированные ошибки. Автоматический откат на прежний `InputData` запрещён.

## Реализованный контракт

| Область | Гарантия |
| --- | --- |
| План модели | `ModelExecutionPlan` хранит задачу, имя операции и неизменяемый снимок параметров. |
| Проверка операции | Операция должна быть моделью из каталога Industrial и поддерживать выбранную задачу. |
| Исполнение | `TensorSupervisedRuntime` создаёт `TensorData`, строит узел через `PipelineBuilder` и ограничивает регистрацию областью `industrial_extension_scope()`. |
| Классификация | Поддерживаются метки, вероятности и полная матрица вероятностей; исходные строковые и разреженные числовые метки восстанавливаются. |
| Регрессия | Поддерживается числовой прогноз; режимы вероятностей отклоняются до вызова модели. |
| Координаты данных | Индексы pandas и имена столбцов переходят в `TensorData` и возвращаются вместе с прогнозом. |
| Мультимодальность | Чистый план фиксирует схемы всех модальностей; преобразователь создаёт согласованный набор `TensorData` с общим индексом. |
| Ошибки | Неизвестная операция, неверное состояние, несовместимая схема, индекс или режим прогноза имеют устойчивый код. |

Проверены операции `pdl_clf`, `pdl_reg`, `kernel_ensemble_clf` и
`kernel_ensemble_reg`. Для каждой пары задача-модель новый путь сопоставлен с
прямым вызовом реализации Industrial на одинаковых данных и параметрах.

## Устранение неявных зависимостей

PDL больше не получает базовые модели из общего файла констант Industrial.
Локальный реестр `fedot_ind.core.models.pdl.base_models` хранит только пути
импорта и загружает выбранную реализацию при создании модели. Поэтому простой
запуск PDL не требует импортировать LightGBM, XGBoost или CatBoost.

Стандартный реестр генераторов Kernel Learning перестал автоматически
подключать прежний общий реестр операций. Совместимая функция явного подключения
сохранена, но основной путь использует тематический реестр. Статистические
методы экстракторов перенесены в локальный модуль рядом с реализациями.

Пути импортов обновлены под объединённый FEDOT. В преобразователе данных удалено
служебное использование `pymonad`: оно лишь оборачивало и сразу разворачивало
список, но делало общий путь Kernel Learning зависимым от версии этой библиотеки.

## Результаты проверок

Проверки выполнялись на Python 3.10 с исходным кодом объединённого FEDOT,
добавленным первым в `sys.path`.

```text
tests/unit/core/kernel_learning: 67 passed
tests/unit/core/models, набор PDL: 99 passed
tests/unit/core/multimodal: 50 passed
tests/unit/integration/fedot: 80 passed
```

Набор интеграции включает сравнение прямых и адаптированных прогнозов,
неизменность плана, сохранение пользовательских индексов, восстановление меток
классов и отказ при неподдерживаемом режиме прогноза. Мультимодальный набор
проверяет воспроизводимость плана, сохранение размеров и индексов, повторное
использование схемы обучения и отказ при неполном наборе источников.

Мост типов данных дополнительно проверен на точном снимке legacy FEDOT:
адресный набор из девяти тестов PDL и преобразования данных пройден полностью.
Расширенный запуск PDL и Kernel Learning дал 167 успешных тестов и один сбой
окружения при импорте отсутствующего нативного модуля
`pyflagser.modules.flagser_pybind`. Ошибка возникает до вызова изменённого кода
и не считается подтверждением или опровержением совместимости алгоритмов.

После обновления импортов карта границы пересобирается командой:

```powershell
python -m tools.fedot_import_boundary --write
python -m pytest tests/unit/integration/fedot/test_import_boundary.py -q
```

## Ограничения

- Прогнозирование временных рядов и обнаружение аномалий не входят в этот этап.
- Мультимодальный преобразователь подготавливает данные, но не строит и не
  обучает составной граф слияния модальностей.
- Профиль `legacy` сохраняется для ещё не перенесённых сценариев. Новый адаптер
  не переключается на него при ошибке.
- Эквивалентность проверяет поведение на контрольных наборах, но не утверждает
  равенство качества на полном наборе промышленных бенчмарков.
- Необязательные базовые модели PDL требуют собственных библиотек только при их
  явном выборе.

Следующий этап `IND-FEDOT-04` должен перенести прогнозирование, обнаружение
аномалий и составное мультимодальное исполнение, после чего статус профиля
`tensor` можно пересмотреть.
