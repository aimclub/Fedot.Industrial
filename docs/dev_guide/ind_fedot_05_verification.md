# IND-FEDOT-05: завершение перехода на новый FEDOT

## Результат

Industrial использует единый контракт FEDOT из коммита
`d1875e7a1ba49c94d13c51d97ec78829bf459ca8` из влитого Pull Request FEDOT
[#1462](https://github.com/aimclub/FEDOT/pull/1462). Переходные профили, прежняя
система подмены реестров и совместимый фасад удалены из исполняемого кода.
Пути классификации, регрессии, прогнозирования и обнаружения аномалий работают
через текущие структуры данных FEDOT и каталог расширений Industrial.

## Граница данных

Функция `ensure_fedot_tensor_data()` является единственной точкой перехода от
внутренних `InputData` к `TensorData`, которые ожидают API, конвейеры и
настройщики текущего FEDOT. Для обучения она создаёт состояние `FIT`. Для
прогноза используется схема обучающих данных и состояние `PREDICT`.

Прогнозирование временных рядов не может неявно создать состояние обучения:
для преобразования проверочной выборки обязательно передать `reference_data`
от обученной модели. Это сохраняет горизонт, схему признаков и трассу данных.

не используются для регистрации операций.

## Новый жизненный цикл

`IndustrialExtensionSession` владеет областью регистрации расширения для одного
экземпляра API. Повторная активация одной сессии не создаёт вторую регистрацию.
Если в одном контексте работают несколько сессий, используется подсчёт
владельцев: закрытие первой сессии не нарушает работу остальных. Закрытая
сессия не может быть активирована повторно.

`FedotIndustrial` активирует расширение перед подготовкой данных, обучением,
прогнозом и загрузкой сохранённого конвейера. Метод `shutdown()` освобождает
регистрацию и вычислительные ресурсы. В стандартном контексте FEDOT расширение
Industrial не регистрируется.

В `IndustrialDispatcher` область регистрации находится внутри Dask-задачи.
Это учитывает контекстную изоляцию реестра FEDOT и не полагается на состояние
процесса, который сформировал задачу.

## Соглашение вызова операций

Поле `runtime_interface` в каталоге принимает два значения:

- `array` — реализация получает массив признаков и целевой вектор;
- `input_data` — адаптер создаёт `InputData` с задачей, типом данных, индексом и
  целевым вектором.

Отложенная фабрика выбирает только объявленное соглашение. Для результата она
извлекает `predict` или `features` из объектов FEDOT, а для вероятностей может
использовать `predict(..., "probs")`, если отдельного `predict_proba()` нет.
Ошибки импорта, создания и вызова модели преобразуются в типизированные ошибки
границы расширения.

Для операций, поддерживающих несколько типов задач, тип нельзя выводить из
значений целевого вектора. Такие операции требуют параметр `task_type` в
ручном конвейере и исключаются из автоматического поиска без контекста задачи.
Это относится, в частности, к нейросетевым моделям и `channel_filtration`.

Выход преобразования нормализуется по объявленному смысловому типу:

- табличные признаки всегда приводятся к матрице «объекты × признаки»;
- образные признаки сохраняют последнюю ось и укладываются в трёхмерное
  ограничение `TensorData`;
- форма прогнозов сохраняет число объектов и горизонт.

Базисные преобразования `eigen_basis`, `wavelet_basis` и `fourier_basis`
принимают `ts`, `image` и `tabular`, как и прежний общий контракт
предварительной обработки Industrial.

## Оптимизация и прогнозирование

`IndustrialEvoOptimizer` возвращает исходный конвейер по истечении времени
только при явном признаке `initial_graphs_prevalidated=True`. API устанавливает
его после фактического обучения и прогноза исходного предположения. Прямой
вызов оптимизатора без такой проверки завершается типизированной ошибкой, а не
возвращает потенциально нерабочий конвейер.

Обработка популяции больше не использует монадический контейнер. Диспетчер
вычисляет только необходимые особи, формирует отложенное резервное вычисление,
регистрирует ошибки оценки и активирует расширение непосредственно внутри
Dask-задачи. Исключения оптимизатора не подавляются пустым индикатором хода
выполнения.

`HybridEnsembleForecaster` по умолчанию явно сообщает об ошибке ветви.
Резервный прогноз последним значением доступен только через
`branch_failure_policy="last_value"` и отмечается в диагностике состоянием
`degraded`.

## Политика зависимостей

`pyproject.toml`, `requirements.txt` и
`tools/platform_support/compatibility.json` указывают на один и тот же FEDOT
SHA. Временный `uv.lock` создаётся из этих данных для каждой поддерживаемой
версии Python и не хранится в репозитории. Проверки отклоняют ветки,
сокращённые идентификаторы, маркеры окружения, дополнительные возможности в
Git-ссылке и повторное объявление FEDOT в дополнительных группах.

Поддерживаются Python 3.10 и 3.11. Python 3.12 остаётся только целью аудита,
пока текущий набор зависимостей не поддерживает его полностью.

## Автоматические ограничения

Команда `python -m tools.fedot_import_boundary` разбирает Python-файлы через
AST и запрещает:

- прежние пути модулей данных FEDOT;
- удалённые модули совместимости Industrial;
- вызовы `setup_repository()` и `setup_default_repository()`;
- прямое изменение внутренних реестров FEDOT.

Проверка не анализирует исторические результаты в JSON и других форматах
данных.

## Известное ограничение FEDOT

В закреплённом коммите FEDOT переход встроенного `TunerBuilder` на
`TensorData` ещё не завершён. Для прежних стратегий настройщик требует
`TensorData`, а классификационный адаптер обращается к полям `InputData`.
Для конвейера расширения `eigen_basis → quantile_extractor → pdl_clf` целевая
функция возвращает конечную метрику и `EvaluationComplete`, но
`SequentialTuner` после адаптации графа записывает `init_metric=inf` и
возвращает исходный конвейер.

Соответствующие тесты настройки в FEDOT отключены с пометкой о будущем
переходе. В Industrial этот сценарий отмечен как строгий `xfail`: текущий
дефект не ломает сборку, а неожиданное прохождение теста остановит CI и
потребует удалить устаревшее ограничение.

До исправления ограничения в FEDOT настройку через `TunerBuilder` не следует
считать поддержанным сценарием Industrial. Ограничение не мешает обычному
обучению и прогнозированию конвейеров.

## Переход для разработчиков

Прежний код:

```python
repository = IndustrialModels()
repository.setup_repository()
try:
    pipeline.fit(data)
finally:
    repository.setup_default_repository()
```

Новый код:

```python
from fedot_ind.integration.fedot.extensions import industrial_extension_scope

with industrial_extension_scope():
    pipeline.fit(data)
```

Для долгоживущего сервиса следует использовать `IndustrialExtensionSession` и
обязательно вызывать `close()` при завершении. Новые исполняемые пути не должны
возвращать старый фасад даже как временную совместимость.

Документы `fed01_verification.md`, `fed03_verification.md`,
`int01_verification.md`, `ind_fedot_03_verification.md` и
`ind_fedot_04_verification.md` описывают промежуточные состояния перехода. Они
сохраняются для истории решений, но не являются действующей инструкцией по
установке.
