# INT-01: граница совместимости с новым FEDOT

Дата проверки: 21 сентября 2026 года.

## Назначение

INT-01 добавляет явную границу между Industrial и двумя несовместимыми
поколениями API FEDOT. Задача этого этапа — проверить новый контракт данных
на минимальном рабочем сценарии, не переводя на него весь исполняемый код
Industrial и не скрывая ошибки автоматическим откатом.

## Профили

| Профиль | FEDOT | Статус | Назначение |
| --- | --- | --- | --- |
| `legacy` | `42f3ba490407a1106e898e94232f2afd0a78f73f` | поддерживаемый | Прежний API `InputData` и основной исполняемый код Industrial |
| `tensor` | `567eb8a958a66fd5e0efc3715c99bfae5e791e01` | экспериментальный | Новый API `TensorData`, `create_data` и реестр расширений FEDOT |

Каждый профиль устанавливается в отдельное окружение. Дополнительные группы
`fedot-legacy` и `fedot-tensor` объявлены взаимоисключающими. Базовые
зависимости пакета не выбирают FEDOT неявно.

## Реализованный контракт

- Чистый слой `fedot_ind.integration.fedot` описывает тип задачи, этап
  обработки, расположение осей, схему признаков, подготовленные данные,
  результат прогноза и состояния исполняемого адаптера.
- Решения по проверке и нормализации данных не импортируют FEDOT и не изменяют
  входные массивы или таблицы.
- Фабрика загружает только явно выбранный адаптер. Если выбранный профиль
  недоступен или завершился ошибкой, другой профиль не подставляется.
- Оба адаптера реализуют одинаковый цикл регрессии `fit` → `predict` → `close`.
- Адаптер `tensor` регистрирует модель через ограниченную область действия
  `extension_scope` и создаёт данные прогноза с `from_data=train_data`.
- Карта прежних импортов хранится в
  `fedot_ind/integration/fedot/import_map.json` и проверяется по
  синтаксическому дереву исходного кода.

На этом этапе общий контракт намеренно ограничен линейной регрессией на CPU.
Классификация, прогнозирование временных рядов, подбор структуры и перенос
остальных путей Industrial относятся к следующим задачам интеграции.

## Проверки

Проверка метаданных и зафиксированных зависимостей:

```bash
python -m tools.platform_support check --json
python -m tools.platform_support export --check
uv lock --check
python -m tools.fedot_import_boundary
```

Все команды завершились успешно. Источник установленного FEDOT в обоих
окружениях подтверждён по `direct_url.json` в соответствии с PEP 610.
Команда `pip check` не обнаружила нарушенных зависимостей.

Проверка чистого слоя и правил платформы:

```bash
python -m pytest tests/unit/platform_support tests/unit/integration/fedot -q
```

Результат: 157 тестов пройдено.

Сквозной тест профиля `tensor`:

```bash
FEDOT_INTEGRATION_PROFILE=tensor \
python -m pytest tests/integration/fedot/test_regression_runtime.py -q
```

Результат: тест пройден. Модель обучилась через FEDOT из снимка
`567eb8a958a66fd5e0efc3715c99bfae5e791e01`, сохранила индексы строк и выдала
ожидаемый прогноз.

Собраны `sdist` и `wheel`. Проверка состава дистрибутива завершилась без
ошибок. После установки wheel в два раздельных окружения выполнены:

```bash
python -I tools/runtime_smoke.py --profile legacy --json
python -I tools/runtime_smoke.py --profile tensor --json
```

Обе проверки завершились успешно и включали настоящее обучение и прогноз.
Для `legacy` дополнительно проверены действующие API Industrial, PDL,
Kernel Learning, Arrow и основной сценарий OKHS.

Полный набор модульных тестов запускался частями из-за ограничений именованных
каналов Windows в песочнице. Основной прогон дал 1722 успешных теста,
24 пропуска, два сбоя окружения и один отдельно исключённый долгий сценарий.
Два сбоя повторно прошли вне песочницы, а `lora_strategy` прошёл отдельно
за 7 минут 12 секунд. В совокупности подтверждены все 1725 исполняемых
модульных тестов; 24 теста штатно пропущены.

## Автоматические проверки

`platform_checks.yml` устанавливает собранный wheel и проверяет:

- профиль `legacy` на Linux и Windows с Python 3.10 и 3.11;
- профиль `tensor` на Linux с Python 3.10 и 3.11;
- настоящий цикл обучения и прогноза профиля `tensor`;
- ожидаемый отказ установки на Python 3.12.

Остальные рабочие процессы явно выбирают `fedot-legacy`, поэтому переходный
этап не меняет их зависимость скрыто.

## Ограничения

- Профиль `tensor` остаётся экспериментальным до переноса основных сценариев
  Industrial и расширения интеграционных тестов.
- Прямые ссылки на Git в дополнительных зависимостях нельзя публиковать в
  PyPI. Публикация остаётся заблокированной до выпуска совместимой версии
  FEDOT и замены ссылок на обычные ограничения версий.
- Проверка `tensor` подтверждает контракт и минимальный рабочий сценарий,
  но не равенство качества моделей между двумя профилями.
