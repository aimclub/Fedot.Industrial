# Составной мультимодальный граф FEDOT и Industrial

## Назначение

`TensorMultimodalClassifier` обучает существующий классификатор FUTURE в графе
FEDOT через декларативный каталог Industrial. Он принимает
`MultimodalDataBundle`, сохраняет имена и формы модальностей, проверяет
совместимость новых данных с обучающими и возвращает `PredictionBatch`
с индексами объектов и порядком классов.

Переход к массивам нужен из-за действующего интерфейса расширений FEDOT.
Это не замена мультимодальной модели обычным классификатором по объединённым
признакам. Перед обучением и предсказанием корневая операция восстанавливает
отдельные тензоры модальностей и передаёт их в
`ConfigurableMultimodalFusionClassifier` и `FutureClassifierTrainer`.
Обучение кодировщиков и объединение представлений выполняет существующий код
FUTURE, а не новый цикл обучения в интеграционном слое.

## Путь данных

1. Для каждой модальности строится план подготовки и свой `TensorData`.
2. Имена и формы без оси объектов сохраняются в неизменяемом `ModalityLayout`.
3. Значения без сокращения размерности упаковываются в общую двумерную матрицу.
4. Отдельные узлы `industrial_modality_slice/<имя>` выбирают свои столбцы.
5. Узел `future_fusion_clf` получает результаты ветвей, восстанавливает формы
   и обучает FUTURE. Его параметр `modality_layout` соответствует порядку,
   в котором FEDOT действительно объединяет ветви, а не порядку исходного словаря.

Четырёхмерные изображения, например GAF, используют промежуточное трёхмерное
представление только для существующего создателя `TensorData`. Полная исходная
форма сохраняется отдельно и восстанавливается до вызова кодировщика.
Изменение высоты и ширины отклоняется даже при неизменном числе элементов.

При предсказании цель из входного набора удаляется до подготовки данных.
Состав модальностей и их формы должны совпадать с обучающими. Индексы объектов
должны быть уникальны; их исходный порядок сохраняется. Лексикографическая
сортировка индексов не используется.

## Пример

```python
import torch

from fedot_ind.core.multimodal.data_bundle import MultimodalDataBundle
from fedot_ind.core.multimodal.enums import MultimodalModality
from fedot_ind.integration.fedot import TensorMultimodalClassifier

generator = torch.Generator().manual_seed(7)
train = MultimodalDataBundle(
    modalities={
        MultimodalModality.raw: torch.randn(12, 1, 32, generator=generator),
        MultimodalModality.stats: torch.randn(12, 6, generator=generator),
    },
    target=torch.tensor([3, 7] * 6),
)
parameters = {
    "fusion_method": "ordinary_bottleneck",
    "d_model": 8,
    "training_config": {
        "epochs": 1,
        "batch_size": 4,
        "seed": 7,
        "device": "cpu",
        "timing_warmup": False,
    },
}
with TensorMultimodalClassifier(parameters=parameters) as model:
    model.fit(train)
    result = model.predict(train.without_target(), probabilities=True)
    print(result.values.shape, result.classes)
```

Это функциональная проверка на синтетических данных, не оценка качества.
Число эпох в реальной задаче задаётся явно в настройках эксперимента.
Вероятности возвращаются для всех классов, включая двоичную классификацию;
порядок столбцов указан в `result.classes`.

Для оценки через локальные исполнители используются
`prepare_multimodal_fusion_data` и `build_multimodal_fusion_pipeline`.
Построение и исполнение графа требуют `industrial_extension_scope()`.
После подготовки разбиений применяется штатный
`PipelineObjectiveEvaluateWithTensorData` и `LocalEvaluationDispatcher`.
Параметры графа остаются обычными сериализуемыми значениями; они не содержат
живой модели или состояния реестра.

## Ограничения

- Проверенный интеграционный путь предназначен для классификации на CPU.
  CUDA и распределённое обучение этим изменением не подтверждаются.
- Схема должна содержать не менее двух поддерживаемых модальностей.
  Числовые метки классов определяются только из обучающей цели; одного класса
  недостаточно для обучения.
- Перенос значений между узлами использует копирование. Измерений ускорения
  и экономии памяти пока нет. На границе модели данные приводятся к `float32`.
- Нельзя менять состав или параметры маршрутизации ветвей без пересборки
  согласованной схемы. Автоматические мутации таких схем этим изменением
  не реализованы и по умолчанию не включены.
- Проверки используют закреплённую копию FEDOT с ранее проверенными
  исправлениями совместимости. Новые исправления в FEDOT для этого пути
  не добавлялись; перенос существующих исправлений остаётся задачей INT-04.
- Мультимодальный сценарий не отменяет отрицательный результат приёмки EVO-04
  и не доказывает готовность процессного исполнения стать режимом по умолчанию.

## Проверки

Тесты находятся рядом с соответствующими контрактами:

- `tests/unit/core/multimodal/test_packing.py`;
- `tests/unit/core/models/test_future_fedot_adapter.py`;
- `tests/unit/integration/fedot/test_multimodal_fusion_runtime.py`;
- `tests/unit/integration/fedot/extensions/test_catalog.py`.

Проверяются восстановление значений и форм, независимость от порядка словаря
и списка родителей графа, реальные обучение и предсказание, отказы до вызова
модели при несовместимой схеме, освобождение графа и возврат реестра в исходное
состояние. В обоих локальных исполнителях составной граф проходит два
разбиения на синтетических данных.
