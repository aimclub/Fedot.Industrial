# Установка и совместимость: PLT-01 и INT-01

Этот документ описывает инструменты разработки и сборки, а не новый API
моделей. Ветка `industrial_release_1.0` готовит будущий выпуск; текущая версия
пакета остаётся `0.5.0`. PLT-01 не переносит алгоритмы в отдельные библиотеки
и не меняет обучение моделей.

## Источники настроек

| Файл | Назначение | Как обновлять |
| --- | --- | --- |
| `pyproject.toml` | Имя, версия, Python, зависимости, дополнительные группы и настройки сборки | Менять вручную и проверять тестами |
| `requirements.txt` | Зависимости профиля `fedot-legacy` | `python -m tools.platform_support export --profile legacy` |
| `requirements-tensor.txt` | Зависимости профиля `fedot-tensor` | `python -m tools.platform_support export --profile tensor` |
| `uv.lock` | Точные версии, источники и контрольные суммы разрешённых зависимостей | `uv lock`, затем проверить установку |
| `tools/platform_support/compatibility.json` | Закреплённый FEDOT, будущая цель миграции и матрица Python | Обновлять только вместе с доказательствами совместимости |
| `setup.py` | Обёртка для инструментов, ожидающих этот файл | Не добавлять второй набор метаданных |

Проверка `check` не заменяет разрешение зависимостей и запуск кода. Она
проверяет структуру настроек, обязательные явно записанные ограничения,
неизменные FEDOT SHA, диапазон Python и актуальность обоих файлов требований.
Ослабление ограничения из матрицы должно сопровождаться её пересмотром;
добавление более строгого ограничения разрешено, если обязательные границы
сохранены. Для проверки всего дерева зависимостей используются `uv lock
--check` и установка с последующим `pip check`.

## Python и FEDOT

| Python | Статус | Проверки |
| --- | --- | --- |
| 3.10 | Поддерживаемый | Установка, импорт wheel, проверки ресурсов и модулей; полный набор unit-тестов в CI |
| 3.11 | Поддерживаемый | Установка, импорт wheel, проверки ресурсов и модулей |
| 3.12 | Только проверка ограничений | Чистые тесты средств разработки; wheel обязан отклонить установку |
| 3.9 и ниже | Не поддерживается | Отказ по метаданным пакета |

Следует использовать актуальный исправляющий выпуск выбранной версии Python.
Поддержка Python 3.12 не заявлена: текущий набор со spaCy 3.5 не прошёл
проверку установки. Issue #125 нельзя закрывать только на основании успешного
запуска чистых тестов на 3.12.

Профиль `legacy` закреплён на
`42f3ba490407a1106e898e94232f2afd0a78f73f`. Этот снимок сохраняет прежние пути
API Industrial и остаётся основным профилем до завершения миграции.

Профиль `tensor` закреплён на ветке `refactor/fedot_1.0.0`, снимок
`c3caa4ee87bd9c7f0bd83b3bc67b5b895bc7b231`. Он предназначен для проверки
нового контракта `TensorData`, имеет статус экспериментального и устанавливается
только в отдельное окружение. Профили взаимоисключающие; автоматический откат
с `tensor` на `legacy` запрещён. Цикл FED-01–03 подготовлен в Pull Request
FEDOT #1462, а граница интеграции Industrial реализована в INT-01.
Равенство номера версии установленного FEDOT не доказывает равенство исходного
кода: команда `environment` проверяет запись происхождения `direct_url.json`
по PEP 610 и отдельно сообщает непроверенный источник.

## Основные ограничения

- `giotto-tda==0.6.2` требует `scikit-learn==1.3.2`. Поэтому
  `dask-ml==2024.4.4`, Dask и Distributed 2024.4.2 заменяют несовместимый набор
  с DaskML 2025. Это ограничение сохраняется до отдельной проверки TDA.
- NumPy остаётся ниже версии 2. SciPy, pandas и sktime ограничены совместимым
  диапазоном; точные версии находятся в `uv.lock`.
- `datasets>=2.21,<3` и `pyarrow>=15,<21` заменяют старый набор, который мог
  успешно установиться и затем упасть при импорте `PyExtensionType`.
  Контрольная проверка создаёт маленький Arrow-набор в памяти.
- `setuptools<81` сохраняется из-за использования `pkg_resources`
  транзитивными зависимостями. Сборка использует setuptools 77 или новее,
  чтобы поддерживать современное описание лицензии.
- Временное ограничение `typing==3.7.4.3` относится только к метаданным
  устаревшей транзитивной зависимости FEDOT/GOLEM: версия 3.10.0.0 объявляет
  Python ниже 3.5. Исполняемый код обязан использовать стандартный модуль
  Python; это проверяет `runtime_smoke`. Ограничение следует удалить после
  исправления требований FEDOT/GOLEM, а не переносить в новые библиотеки.
- Dask, fastai и PyTorch пока остаются основными зависимостями: существующие
  модули импортируют их напрямую. Выделять их в дополнительные группы до
  изменения этих границ небезопасно.

Группа `dev` содержит средства тестирования и сборки; `notebooks` содержит
Jupyter, nbconvert и ipykernel. Industrial не объявляет их основными
зависимостями. При этом старый FEDOT сам требует pytest транзитивно;
устранение такого смешения относится к последующим этапам интеграции.

`pycaputo>=0.10.1`, `pymittagleffler>=0.1.3` и `ripserplusplus` удалены из
общего списка. Первые два требуют NumPy 2; последний требует отдельной проверки
нативной сборки и CUDA. Это не означает, что исследовательские сценарии Deep
OKHS теперь поддерживаются без этих пакетов. Их следует запускать в отдельном
исследовательском окружении с собственным зафиксированным набором зависимостей.
Основной OKHS использует уже существующую обработку отсутствующего
`pymittagleffler`; PLT-01 не добавляет подмену результатов.

## Установка разработчика

Создать новое окружение Python 3.10 или 3.11; не обновлять старое окружение
исследовательских запусков на месте.

```bash
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell вместо предыдущей строки:
# .venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e ".[dev,fedot-legacy]"
python -m tools.platform_support check --json
python -m tools.platform_support environment --profile legacy --json
python -m pip check
```

Для Jupyter добавить `python -m pip install -e ".[notebooks]"`.
Для стандартной установки точных версий: `uv sync --frozen --extra dev
--extra fedot-legacy`.
Нужен uv 0.8.17; Poetry больше не является средством установки этого проекта.
На Linux стандартный источник PyTorch может загружать большие CUDA-библиотеки.
Это не служит подтверждением работоспособности GPU.

Для проверки нового API следует создать второе окружение и выполнить:

```bash
python -m pip install -e ".[dev,fedot-tensor]"
python -m tools.platform_support environment --profile tensor --json
FEDOT_INTEGRATION_PROFILE=tensor python -m pytest tests/integration/fedot/test_regression_runtime.py -q
```

Не устанавливайте `fedot-legacy` и `fedot-tensor` в одно окружение.

Для лёгкого CPU-окружения используется тот же способ, что и в CI:

```bash
python -m pip install "uv==0.8.17"
python -m pip install --index-url https://download.pytorch.org/whl/cpu "torch==2.5.1" "torchvision==0.20.1"
uv export --frozen --extra dev --extra fedot-legacy --no-hashes --no-emit-project --output-file .local/industrial-locked.txt
python -m pip install -r .local/industrial-locked.txt
python -m pip install --no-deps -e .
python -m pip check
```

Сначала создать каталог `.local`, если его нет. Такой экспорт воспроизводит
версии из lock-файла, но не переключает уже установленную CPU-сборку PyTorch
на CUDA. Возможности CUDA и распределённого обучения проверяются отдельными
этапами дорожной карты.

## Сборка и проверки

```bash
python -m tools.platform_support export --check
uv lock --check
python -m pytest tests/unit/platform_support tests/unit/integration/fedot -q
python -m build
python -m tools.distribution_check --json
```

`python -m build` сначала создаёт sdist, затем собирает wheel из sdist.
Так проверяется, что в исходном архиве не забыты входы сборки. Сборка не
устанавливает ML-зависимости. `distribution_check` проверяет метаданные,
основные и дополнительные зависимости, JSON/CSV-ресурсы и отсутствие данных,
примеров, тестов и локальных инструментов внутри дистрибутива.

Для проверки именно установленного wheel создать отдельное окружение,
установить зависимости, затем `python -m pip install --no-deps dist/*.whl`
(в PowerShell подставить найденный путь wheel). Из корня исходного репозитория:

```bash
python -I tools/runtime_smoke.py --profile legacy --json
```

Режим `-I` не позволяет каталогу исходников скрыть дефекты wheel.
Команда проверяет расположение и версию установленного пакета, ресурсы
реестра, CPU-вычисление, API выбранного профиля, настоящий сценарий обучения
и прогноза, а для `legacy` также текущие API Industrial/PDL/Kernel Learning,
Arrow-набор и основной OKHS без дополнительных исследовательских пакетов. Сообщения
о ходе проверки идут в stderr, итоговый JSON остаётся пригодным для обработки.
Это короткая проверка установки, а не оценка качества обученных моделей.

## Проверки GitHub Actions

- `package_build.yml`: одна процедура сборки для проверок и публикации.
- `platform_checks.yml`: чистые проверки на 3.10/3.11/3.12, установка wheel
  с профилем `legacy` на Linux/Windows, сквозная проверка профиля `tensor`
  на Linux 3.10/3.11 и отдельная проверка отказа установки на 3.12.
- `poetry_unit_test.yml`: прежнее имя файла сохранено для ссылок и статуса
  проверки; выполнение переведено на pip и точные версии из `uv.lock`.
- `integration_tests.yml`: тот же зафиксированный набор зависимостей.
- `pypi_release.yml` и `python-publish.yml`: используют общую сборку и
  проверку пригодности публикации.

В этой подготовительной ветке публикация в PyPI **заблокирована осознанно**:
PyPI не принимает зависимости с прямыми Git URL. Местная установка принимает
такой wheel, но `distribution_check --pypi` возвращает ошибку до обращения
к секретам публикации. Перед настоящим выпуском требуется совместимый
опубликованный выпуск FEDOT, замена Git-ссылки в единственном источнике
метаданных, обновление матрицы и lock-файла и повторная проверка установки.
Не следует удалять зависимость из wheel только ради обхода проверки.
См. [правила setuptools о прямых URL](https://setuptools.pypa.io/en/latest/userguide/dependency_management.html#direct-url-dependencies).

## Приёмка PLT-01

- Тесты новых средств разработки и проверки составов проходят.
- Экспорт обоих файлов требований совпадает с `pyproject.toml`, lock-файл актуален.
- Wheel и sdist собираются без установки ML-библиотек.
- Новая установка на 3.10/3.11 проходит проверку зависимостей и импортов.
- Результаты локальной проверки и ограничения CI записаны в отчёте изменений.
- #162/#191 закрываются только после проверки их конкретных требований;
  #125 остаётся открытым до реальной поддержки 3.12.

PLT-01 не утверждает готовность всей ветки к выпуску 1.0 и не меняет состояние
GitHub issues автоматически.

## Приёмка INT-01

- Базовые зависимости не выбирают FEDOT неявно.
- `legacy` и `tensor` устанавливаются как взаимоисключающие дополнительные группы.
- Общий чистый слой не импортирует FEDOT; конкретный адаптер загружается лениво.
- Оба профиля выполняют один контракт регрессии `fit` → `predict` без отката.
- Карта прежних импортов воспроизводима и проверяется тестом.
- Профиль `tensor` проверяется в CI на Python 3.10 и 3.11 по точному SHA.

## Манифест Industrial: IND-FEDOT-02

Профиль `tensor` больше не подменяет файлы реестра FEDOT и методы
`PipelineSearchSpace`. Операции Industrial описаны в
`fedot_ind/integration/fedot/extensions/catalog.json`: для каждой операции
указаны тип, поддерживаемые задачи и данные, вычислительная основа, параметры и
путь к реализации. Загрузчик проверяет схему JSON до построения объектов FEDOT.

`register_industrial_extension(dry_run=True)` строит план регистрации без
изменения реестра. Обычный вызов регистрирует манифест один раз, а повторный
возвращает состояние `already_registered`. Конфликт версий и неизвестная
операция представлены типизированными ошибками. Временная регистрация доступна
через `industrial_extension_scope()` и восстанавливает предыдущее состояние
реестра при выходе из блока.

Класс `IndustrialModels` сохранён как совместимый фасад. В профиле `tensor` он
использует манифест; прежние подмены собраны в отдельном модуле
`fedot_ind.integration.fedot.legacy_repository` и загружаются только для
профиля `legacy`. Импорт фасада сам по себе не регистрирует операции и не меняет
классы FEDOT.

Пространство настройки параметров теперь создаётся функцией
`build_industrial_pipeline_search_space()`. Каждый вызов возвращает независимый
объект, поэтому пользовательские настройки одного запуска не меняют следующие
запуски.

Манифест использует отложенные фабрики: проверка и регистрация не импортируют
реализации моделей. Полный перевод прежних реализаций с `InputData` на
`TensorData`, а также проверка обучения и прогноза относятся к этапам
`IND-FEDOT-03` и `IND-FEDOT-04`. До их завершения профиль `tensor` подтверждает
контракт обнаружения и регистрации операций, но не равен полной поддержке всех
моделей Industrial.

### Приёмка IND-FEDOT-02

- Каталог и манифест проходят проверку схемы FEDOT.
- Повторная регистрация не создаёт дубликаты.
- Импорт `IndustrialModels` не меняет реестр и классы FEDOT.
- Неизвестная операция возвращает ошибку `operation_not_found`.
- Настройка параметров не зависит от глобальной подмены
  `PipelineSearchSpace.get_parameters_dict`.
- Старые подмены доступны только через явно выбранный профиль `legacy`.
