# Римановы признаки для многоканальных временных рядов

`RiemannExtractor` преобразует каждый временной ряд в один или несколько наборов
симметричных положительно определённых матриц (SPD), рассматривает их как точку
произведения SPD-многообразий и возвращает обычный вещественный вектор признаков.

Реализация находится в
`fedot_ind/core/operation/transformation/representation/manifold` и использует
PyTorch. Поддерживаются только вещественные симметричные матрицы и одинаковая
структура блоков у всех объектов на обучении и инференсе.

## 1. Пайплайн

Вход имеет форму `(n_samples, n_channels, n_times)`. Двумерный массив
`(n_samples, n_times)` интерпретируется как набор одноканальных рядов.

```text
временной ряд
    -> несколько SPD views
    -> shrinkage каждого view
    -> произведение атомарных SPD-блоков
    -> общий product-центроид или product-центроиды классов
    -> tangent-признаки и/или расстояния MDM
    -> один плоский вектор признаков
```

Пусть builder с именем `v` строит для объекта `i` набор матриц

$$
\mathcal C_i^{(v)} =
\left(C_i^{(v,1)},\ldots,C_i^{(v,B_v)}\right),
\qquad C_i^{(v,b)}\in\operatorname{SPD}(n_{v,b}).
$$

Тогда объект живёт в произведении

$$
\mathcal M =
\prod_v\prod_{b=1}^{B_v}\operatorname{SPD}(n_{v,b}).
$$

Плотная block-diagonal матрица при этом не строится: блоки хранятся и
обрабатываются отдельно.

Для пользовательского веса view `alpha_v` вес одного его блока равен

$$
\gamma_v = \frac{\alpha_v}{B_v}.
$$

Поэтому спектральный view не получает больший суммарный вес только из-за
большого количества частотных блоков. Квадрат расстояния в произведении:

$$
d_{\mathcal M}(\mathcal C_i,G)^2 =
\sum_v\sum_{b=1}^{B_v}
\gamma_v\,d_v\!\left(C_i^{(v,b)},G^{(v,b)}\right)^2.
$$

Доступны три метрики:

$$
\begin{aligned}
d_{\mathrm{euclid}}(C,G)
    &= \lVert C-G\rVert_F,\\
d_{\mathrm{logeuclid}}(C,G)
    &= \lVert \log C-\log G\rVert_F,\\
d_{\mathrm{riemann}}(C,G)
    &= \left\lVert\log\left(G^{-1/2}CG^{-1/2}\right)\right\rVert_F.
\end{aligned}
$$

Перед геометрическими операциями применяется shrinkage:

$$
\widetilde C=(1-\lambda)C+\lambda\mu I,
\qquad 0\leq\lambda\leq1,
$$

где `mu` определяется средним следом соответствующего структурированного view.
Спектральные операции дополнительно ограничивают собственные значения снизу
машинным epsilon или значением `centroid_params["eigenvalue_floor"]`.

## 2. Доступные SPD views

Один `view` задаётся словарём с полями `name`, `builder`, `weight`,
`shrinkage` и `params`.

| `builder` | Результат | Параметры |
|---|---|---|
| `covariance` | Одна матрица ковариации каналов размера `C x C` | `estimator`, `estimator_params` |
| `grouped_covariance` | Несколько ковариационных блоков для последовательных групп каналов | `group_sizes`, `estimator`, `estimator_params` |
| `cospectra` | По одной матрице взаимного спектра каналов на частотный бин | `window`, `overlap`, `fmin`, `fmax`, `fs` |

### 2.1. Covariance

Для каждого объекта ковариация оценивается по временной оси:

$$
C_i = \frac{1}{q}\sum_t
(x_i(t)-\bar x_i)(x_i(t)-\bar x_i)^\top.
$$

Доступны estimators `scm`, `cov`, `corr`, `lwf`, `oas`, `mcd` и `hub`.
`mcd` и `hub` временно используют CPU fallback через PyRiemann; остальные
реализованы непосредственно на Torch.

### 2.2. Grouped covariance

Каналы последовательно делятся на группы. Например, `group_sizes=[2, 3]`
для пяти каналов создаёт точку

$$
(C_i^{(1)},C_i^{(2)})\in
\operatorname{SPD}(2)\times\operatorname{SPD}(3).
$$

Сумма `group_sizes` должна совпадать с числом каналов.

### 2.3. Co-spectra

Ряд разбивается на перекрывающиеся окна, к ним применяется окно Ханна и FFT.
Для каждого выбранного частотного бина `f_k` строится матрица

$$
S_i(f_k)_{cd} =
\operatorname{Re}\left[
\frac{1}{Z}\sum_w
\overline{X_{i,w,c}(f_k)}X_{i,w,d}(f_k)
\right].
$$

Здесь `c` и `d` — каналы, `w` — номер временного окна, а `Z` — нормировка.
Один блок сравнивает каналы на одной и той же частоте: разные частоты внутри
матрицы не смешиваются. Если выбрано `F` частот, результат принадлежит

$$
\operatorname{SPD}(C)^F.
$$

Значение `window` автоматически округляется вверх до степени двойки.

## 3. Центроиды

`centroid_type="mean"` вычисляет среднее отдельно в каждой координате
произведения. Веса views не меняют сами координаты среднего, но используются
при масштабировании признаков и вычислении product-distance.

`centroid_type="median"` решает одну связанную задачу

$$
G^* = \arg\min_G\sum_i d_{\mathcal M}(\mathcal C_i,G).
$$

Все компоненты медианы обновляются с общими Weiszfeld-весами объектов. Таким
образом, product-median не является независимым набором медиан блоков.

Для MDM доступны два scope:

- `class`: один product-центроид на каждый отсортированный класс;
- `global`: один product-центроид по всей обучающей выборке.

## 4. Выходные признаки

### Tangent

Для каждого блока вычисляется логарифмическая или евклидова карта относительно
обученного центроида. Симметричная матрица векторизуется по верхнему
треугольнику; внедиагональные элементы умножаются на `sqrt(2)`, чтобы сохранить
норму Фробениуса.

$$
z_i^{\mathrm{tan}}=
\operatorname{concat}_{v,b}
\left[
\sqrt{\gamma_v}\,
\operatorname{upper}\left(
\operatorname{Log}_{G^{(v,b)}}C_i^{(v,b)}
\right)
\right].
$$

Размерность tangent-части:

$$
p_{\mathrm{tan}}=
\sum_v\sum_{b=1}^{B_v}\frac{n_{v,b}(n_{v,b}+1)}{2}.
$$

### MDM

Для каждого product-центроида `G_k` возвращается одно агрегированное расстояние:

$$
z_{i,k}^{\mathrm{mdm}}=
\sqrt{
\sum_v\sum_b\gamma_v
d_v\!\left(C_i^{(v,b)},G_k^{(v,b)}\right)^2
}.
$$

При `mdm_centroid_scope="class"` получается `K` признаков по числу классов,
при `global` — один признак.

Параметр `feature_mode` определяет итог:

| Значение | Результат |
|---|---|
| `tangent` | Только tangent-координаты |
| `mdm` | Только product-MDM расстояния |
| `both` | Сначала tangent-координаты, затем MDM |

Class MDM требует `target` во время обучения. Для регрессии `both`
автоматически становится `tangent`, а явный режим `mdm` отклоняется.

Например, для четырёх каналов raw covariance даёт 10 tangent-признаков,
две группы `[2, 2]` дают ещё `3 + 3`, а co-spectra с `F` частотами — `10F`.
При двух классах итог режима `both` имеет размерность `18 + 10F`.

## 5. Прямой вызов `RiemannExtractor`

```python
import numpy as np

from fedot.core.data.data import InputData
from fedot.core.repository.dataset_types import DataTypesEnum
from fedot.core.repository.tasks import Task, TaskTypesEnum
from fedot_ind.core.operation.transformation.representation.manifold.riemann_embeding import (
    RiemannExtractor,
)


def as_classification_data(X, y=None):
    return InputData(
        idx=np.arange(len(X)),
        features=X,
        target=y,
        task=Task(TaskTypesEnum.classification),
        data_type=DataTypesEnum.image,
    )


rng = np.random.default_rng(42)
X_train = rng.normal(size=(12, 4, 256))
y_train = np.repeat([0, 1], 6)
X_test = rng.normal(size=(3, 4, 256))

params = {
    "views": [
        {
            "name": "raw",
            "builder": "covariance",
            "weight": 1.0,
            "shrinkage": 0.1,
            "params": {"estimator": "scm", "estimator_params": {}},
        },
        {
            "name": "groups",
            "builder": "grouped_covariance",
            "weight": 1.0,
            "shrinkage": 0.1,
            "params": {
                "group_sizes": [2, 2],
                "estimator": "oas",
                "estimator_params": {},
            },
        },
        {
            "name": "spectral",
            "builder": "cospectra",
            "weight": 1.0,
            "shrinkage": 0.1,
            "params": {
                "window": 64,
                "overlap": 0.75,
                "fmin": 1.0,
                "fmax": 20.0,
                "fs": 100.0,
            },
        },
    ],
    "feature_mode": "both",
    "tangent_metric": "riemann",
    "mdm_metric": "riemann",
    "mdm_centroid_scope": "class",
    "centroid_type": "mean",
    "centroid_params": {},
    "torch_device": "cpu",
    "torch_dtype": "float64",
    "use_cache": False,
}

extractor = RiemannExtractor(params)
train_features = extractor.fit_transform(
    as_classification_data(X_train, y_train)
).predict
test_features = extractor.transform(
    as_classification_data(X_test)
).predict
```

Для train следует использовать `fit_transform` либо пару
`fit -> transform_for_fit`: рассчитанные SPD views кешируются на один вызов и
не строятся повторно. Обычный `transform` после обучения применяет сохранённые
центроиды к новым данным. Вызов `transform` до `fit` выполняет auto-fit с
предупреждением и не должен использоваться для test data из-за утечки данных.

## 6. Вызов через kernel-learning adapters

Default-конфигурация содержит один raw covariance view и режим `both` с
class MDM:

```python
from fedot_ind.core.kernel_learning.generators.adapters import create_feature_generator

generator = create_feature_generator(
    "riemann_extractor",
    torch_device="cpu",
)

train_bundle = generator.fit_transform(
    X_train,
    y_train,
    task_type="classification",
)
test_bundle = generator.transform(X_test)

train_features = train_bundle.features
test_features = test_bundle.features
assert train_bundle.diagnostics["source"] == "fedot_industrial_operation"
```

Для собственной конфигурации можно собрать тот же adapter явно:

```python
from fedot_ind.core.kernel_learning.generators.adapters import (
    BudgetedRepositoryFeatureGeneratorAdapter,
    GeneratorBudgetPolicy,
    OperationSpec,
)

generator = BudgetedRepositoryFeatureGeneratorAdapter(
    name="riemann_extractor",
    operation_specs=(
        OperationSpec(
            name="riemann_extractor",
            module_path=(
                "fedot_ind.core.operation.transformation.representation."
                "manifold.riemann_embeding"
            ),
            class_name="RiemannExtractor",
            params=params,
            use_torch=True,
            fit_transform_on_fit=True,
        ),
    ),
    torch_device="cpu",
    budget_policy=GeneratorBudgetPolicy(fallback_generator="identity"),
)

train_bundle = generator.fit_transform(X_train, y_train)
test_bundle = generator.transform(X_test)
```

`fit_transform_on_fit=True` принципиален: adapter вызывает нативный stateful
`fit_transform`, а inference использует уже обученные центроиды. Budgeted
adapter при недоступности операции переключается на fallback; это видно по
`bundle.diagnostics["source"] == "budgeted_fallback"`.
