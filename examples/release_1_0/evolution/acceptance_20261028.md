# Короткая парная проверка Dask

Проверены последовательный режим и Dask с одним управляемым сеансом на поиск.
Данные: Airline из sktime, 15 эволюционных поколений после начальной популяции,
начальное значение генератора 42, четыре работника Dask, предел поиска 300 секунд на режим. Модели и их
параметры прежние; настройки Torch и пороги EVO-04 не менялись. Кэш оценок
конфигураций не добавлялся. Приёмка EVO-04 этим примером не пересматривается.

| --- | ---: | ---: |
| Подготовка и поиск от запуска дочернего Python, с | 75,084 | 64,804 |
| Полный дочерний процесс под внешним ограничителем, с | 76,188 | 66,354 |
| Подготовка пакетов на координаторе, с | 0,189 | 0,252 |

Оба поиска завершились. Совпали TRAIN и внутренние разбиения, мультимножества
фактических попыток и оценок, выбранный граф и итоговая метрика. Настройки Torch
до и после одинаковы. Единственный сеанс Dask закрыт владельцем. TEST не участвовал
в поиске и подборе; итоговая оценка выполнена после заморозки вычислительного кода.
После завершения не осталось наблюдавшихся процессов этих запусков: проверены
PID вместе со временем создания, без остановки чужих процессов.

Это одна пара на одной машине при неконтролируемой фоновой нагрузке, не устойчивая
оценка ускорения. Суммы времени работников не равны длительности поиска. Прочее
время включает запись диагностики. Старое поле `wall_seconds` отсчитывается позже
первых импортов; для полного сценария здесь использовано время внешнего ограничителя.

Первоначальный проверяющий скрипт ошибочно потребовал нулевого сохранения готовых
fitness у выживших особей GOLEM. В обоих режимах таких сохранений 44; это прежний
механизм, не новый кэш конфигураций. Первоначальный отрицательный отчёт сохранён
как `acceptance_initial_validator.json`. Исправлено только условие проверяющего
скрипта: одинаковое штатное сохранение оценок и одинаковые фактические попытки.
После этого артефакты проверены повторно без обучения; все 11 условий выполнены.
Модели, бюджеты и критерии EVO-04 ради этого не менялись. Вычислительные файлы не
редактировались между запусками; версия проверяющего скрипта сохранена отдельно.

Исходные JSON, JSONL, CSV, HTML Dask, рисунки и контрольные суммы находятся локально:
`examples/artifacts/cloud_bundle/evolution_parallelism/pair_acceptance_20261028_v1`.
Они не включены в Git и пока не опубликованы в облаке. Соседний `report/` содержит
таблицы этапов, попыток, нагрузки и графики. `acceptance.json` хранит SHA-256 входов.
Все 59 входных файлов проверены по контрольным суммам. Между снимком запуска и
закоммиченными файлами отличается только проверяющий скрипт `acceptance.py`;
вычислительный код, включая все модули оптимизатора, остался неизменным.

Предварительная проверка не запускает обучение:

```bash
python -m benchmark.industrial.experiments.evolution_parallelism.acceptance --output-dir ./pair_check
```

Для воспроизведения добавьте `--execute` и укажите новый, ещё не существующий каталог.
