# Исправленный план B/D с настройкой генераторов

Этот документ заменяет порядок будущих действий из
`cyclic_search_plan_20261104.md`, но не меняет исторические отчёты и результаты.

1. Исходное сравнение A/B/C не доводим до завершения. Оставшиеся 65 поисков

2. Переходим к отдельной исправленной версии с настройкой генераторов и D.
3. Для нового сравнения оставляем только B и D.
4. Историю сохраняем обязательно; графики строим штатными средствами FEDOT/GOLEM,
   если их входные данные и смысл соответствуют нужному показателю.

Прежние 33 попытки и 127 квитанций следующей версии остаются неизменными.
Незавершённый Airline/C/777 сохраняется отдельно, не объявляется результатом.
Причина остановки контроллера не установлена. Старый status.json со значением
running не является доказательством работающего процесса.

Документ фиксирует состояние на момент согласования плана. Тогда исполняемый
код ещё не менялся, D не была реализована и новые обучения не запускались.
Ход выполнения и результаты проверок отражены отдельно в
`bd_implementation_20261105.md`.

## Почему сравниваем с B

B использует постоянную смесь структурных и параметрических действий.
D чередует поиск структуры и настройку параметров фиксированной структуры.
Это позволяет проверить порядок действий относительно постоянного смешивания.
C добавляет другую временную последовательность этапов и проблему пропуска
уточнения на долгих поколениях, поэтому его оставляем только в архиве.

Новый B — не повтор старого B: исправления, расширенное пространство параметров
и сохранение истории применяются к обоим новым вариантам. Сравнивать новый D
с архивным B вместо нового парного запуска нельзя.

Одинаковы в B/D: данные и разбиения, набор операций, начальные условия,
допустимые параметры, правила ведения архива структур, ограничения сложности,
исполнитель Dask, seeds, метрики и вычислительный бюджет. Параметрический
подбор не должен быть доступен только D: B также получает весь каталог.
Скрещивание в первом B/D остаётся выключенным; его включение — отдельный фактор.

## Настройка генераторов: обязательная часть

### Что уже есть в коде

В `fedot_ind/core/tuning/search_space.py` есть пространства параметров для
quantile_extractor, wavelet_basis, fourier_basis и hankelisation. Прежний
ограниченный эксперимент их не использовал: `search_policy/defaults.json`
содержит только сетки alpha, C и max_depth. Для quantile_extractor_torch
отдельная запись в просмотренном общем каталоге отсутствует.

Добавление имён в JSON недостаточно. `ParameterSearchPreparation` требует
явных исходных значений и сохраняет изменённые значения только для объявленных
сеток. Нельзя допустить, чтобы выбранные параметры генераторов сбрасывались
на значения по умолчанию перед обучением или после выбора победителя.

### Обязательный охват первой версии

| Узел | Параметры, которые надо включить или проверить |
| --- | --- |
| quantile_extractor | window_size, режим окон, stride при активном окне, add_global_features |
| quantile_extractor_torch | соответствующие поддерживаемые настройки; отдельная проверка семантики Torch |
| wavelet_basis | wavelet, n_components, low_freq; совместимость семейства вейвлета и представления |
| fourier_basis | threshold, low_rank, approximation; совместимость output_format с потомками |
| hankelisation | window_size, stride, ограничения относительно длины внутренних TRAIN-блоков |
| Конечные модели | прежние сетки alpha, C и max_depth доступны обоим вариантам |

Численные наборы значений фиксируются до новых обучений на основе общего
каталога и реальной реализации. Манифест эксперимента задаёт ограниченное
подмножество общего пространства, а не второй независимый каталог.
Значения по умолчанию входят в разрешённое пространство.

Важные условия:

- У NumPy/Torch window_size задаётся не так же, как у Hankel: в статистических
  окнах он переводится в долю длины ряда. Единицы и округление надо описать явно.
- stride имеет смысл только в соответствующем режиме окон. Неактивные параметры
  не должны создавать фиктивные новые конфигурации и расходовать оценки.
- n_components не всегда создаёт новое представление: результат зависит от
  семейства вейвлета и числа доступных компонент.
- output_format меняет семантику представления, а не только численную настройку.
  Такой переход требует проверки совместимости со всеми потомками; иначе он
  не допускается как обычная параметрическая мутация.
- Изменение размерности признаков допустимо только при корректной передаче
  данных: сохраняются согласованные индексы, цели и временные границы.
  Параллельные ветви не объединяются по случайному совпадению размеров.
- Допустимость определяется по обучающим блокам, не по TEST и не по качеству
  отложенного TRAIN-контроля. Ошибочные параметры не заменяются молча.
- В идентичности кандидата и ключах локальных признаков учитываются все
  параметры генераторов. Это не разрешение на отложенное ранее переиспользование
  оценок или обученных моделей между кандидатами.
- Параметры выполнения, device, число потоков, seed, use_cache и горизонт
  прогноза не являются пространством подбора качества.

Для консервативной фазы не строим полный декартов перебор всех узлов.
Нужен ограниченный совместный поиск параметров генераторов и конечной модели
по нескольким перспективным структурам. Каждая обученная конфигурация учитывается
в общей стоимости; вложенный тюнер не может скрывать дополнительные fit.

## D: явные повторяющиеся фазы

```text
активный поиск → настройка генераторов и моделей → активный поиск → настройка
```

Во время настройки структура и набор операций выбранного семейства фиксированы.
Меняются разрешённые параметры, а проверка совместимости сохраняется.
Результат настройки каждого семейства передаётся следующему активному циклу.
Нельзя свести настройку к одному победителю и потерять остальные перспективные
структуры. Идентичность структуры отделяется от идентичности всей конфигурации.

Переключение задаётся для ограниченных пачек кандидатов, а не только для целых
поколений. Выполняющиеся fit не прерываются ради смены фазы. Планировщик заранее
ограничивает активную часть и резервирует время настройки. Исчерпанная локальная
сетка приводит к переходу фазы, а не к бессмысленным повторам. Незавершённые
циклы и задержки переключения фиксируются явно.

Нужен отдельный контракт фазы: текущий MutationMix запрещает 100% параметрических
действий. Простое переименование стадий в старом JSON не реализует консервативную
фазу. Также глобальное время не должно обнуляться при начале нового цикла.

Постоянное смешивание B и циклический D используют сопоставимое распределение
возможностей структурных и параметрических действий. В журнале показываются
не только плановые доли, но и фактическое число оценок, их затраты и пропуски.
Иначе разницу качества нельзя будет уверенно отнести к чередованию фаз.

## История и штатная визуализация

Для B и D обязательны keep_history=True и сохранение полноценной OptHistory.
Каждое завершённое поколение сохраняется атомарно, дополнительно сохраняются
архив всех успешных оценок до усечения потомков и итоговый выбор модели.
В историю входят исходные параметры, метрики, связи родителей и потомков,
операторы, фазы, временные отметки, seeds, отказы и сведения об окружении.
Не надо сериализовать сырые данные и тяжёлые обученные модели внутрь истории.

История должна переживать сбой контроллера: уже записанные поколения доступны
для просмотра без повторного обучения. Это не означает автоматическое
восстановление работающего оптимизатора с середины поколения.

Штатные представления FEDOT/GOLEM:

- fitness_line: лучшее значение по поколениям и времени;
- fitness_box: распределения качества в поколениях;
- PipelineVisualizer / PipelineHistoryVisualizer: выбранные графы и история;
- operations_kde и operations_animated_bar: динамика операций;
- diversity_line: разнообразие популяций;
- genealogical_path: происхождение выбранных решений при сохранённых связях.

Теги новых Industrial-операций должны поддерживаться визуализатором.
Отдельные дополнения допустимы для фаз, затрат, отказов и изменения параметров,
если в штатном интерфейсе нет соответствующего графика. Они опираются на ту же
историю, не заменяют её независимой реконструкцией. Рендеринг выполняется после
поиска, не внутри оцениваемого fit. Расходы записи истории измеряются отдельно
и одинаково учитываются в B/D.

## Порядок реализации: отдельные проверяемые блоки

1. **Контракты и причины отказов.** Исправить передачу исходных ошибок через
   обёртки, разобрать второй Fourier и ошибки Boron на внутренних TRAIN-блоках.
   Проверить оконные режимы NumPy/Torch и другие пути, которые откроет настройка.
   Оптимизировать только подтверждённые узкие места с проверкой неизменности
   результатов на прежних конфигурациях.
2. **Каталог настройки генераторов.** Подключить общий типизированный каталог,
   ограниченный профиль эксперимента, условные параметры и проверки границ.
   Убедиться, что параметры проходят до реального исполнения и не сбрасываются.
3. **Полная история и визуализации.** Сохранить поколения, родословную, архив
   до усечения и параметры; проверить загрузку сохранённой OptHistory и
   формирование штатных рисунков без fit. Одинаково включить для B и D.
4. **Циклический планировщик D.** Реализовать переходы фаз, локальные бюджеты,
   несколько семейств и перенос улучшенных конфигураций. Тестами проверить
   неизменность структуры в консервативной фазе, принадлежность значений
   разрешённым пространствам, монотонность глобальных часов и архива.
5. **Новый допуск и B/D.** Заморозить новую версию кода и каталогов, выполнить
   короткие проверки двух вариантов на трёх типах задач и оконных крайних
   случаях. Не выдавать прежний допуск frozen_07 за проверку нового пространства.
   После успешного допуска запускать только новую матрицу B/D.

Каждый кодовый блок оформляется отдельным коммитом с проверками. Изменения
не добавляются в старые замороженные каталоги.

## Матрица и критерии сравнения

Сохраняем те же 15 источников, пять seeds и фиксированные разбиения TRAIN.
Новая полная матрица: 15 × 2 × 5 = **150 поисков**, а не 225. Уже посчитанные
старые A/B/C не заменяют новые B/D. Повторная загрузка TEST не требуется.

Бюджеты остаются 600 секунд на поиск, 90 на кандидата, 1200 на процесс;
четыре процесса Dask и прежние настройки Torch. Горизонт, метрики, цель
15 поколений и предел доли отказов 10% не ослабляются. OKHS-FDMD не трогаем.

Численные пространства генераторов — явное расширение нового протокола,
а не изменение старого frozen_07. Исходные массивы, метки и разбиения
сверяются с прежними хешами; новый пакет фиксирует собственные код и каталог.

До запуска фиксируем расписание, бюджеты фаз и правило отбора семейств.
Официальный TEST и отложенный TRAIN-контроль не используем для их настройки.
Внутренняя проверка служит поиску, контроль — оценке уже выбранной процедуры.
Показываем все seeds, статусы и разброс, а не только лучший граф.

Основные показатели: качество при одинаковом бюджете, затраты CPU/памяти/времени,
доля отказов, реальное участие обоих типов фаз и вклад настройки генераторов.
Число уникальных графов остаётся диагностикой. Неудачный допуск, пропущенная
консервативная фаза или недостигнутые поколения не скрываются и не превращаются
в успех изменением подписи.
