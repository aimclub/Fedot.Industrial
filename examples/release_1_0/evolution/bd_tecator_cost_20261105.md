# Ускорение допуска B/D на Tecator

## Почему остановился gate_03

Tecator/B завершил 10 поколений вместо требуемых 15. Успешных оценок 86,
отказов 2; оба последних кандидата остановлены по общему сроку, а не по
90-секундному пределу отдельного кандидата. Уменьшать требование к поколениям
или увеличивать бюджет ради допуска нельзя.

Анализ выполнен по сохранённым журналам, без обучения:

| Участок | Время | Что именно измерено |
| --- | ---: | --- |
| Выполнение пачек | 570,69 с | Реальное время ожидания оценок |
| Подготовка пачек | 1,72 с | Подготовка графов и заданий |
| Применение результатов | 2,70 с | Обработка результатов на координаторе |
| Остальное время координатора | 33,23 с | Остаток времени, включая часть отчётных расходов |
| Начало сеанса Dask | 8,98 с | Отдельно записанный запуск исполнителей |

Эти строки нельзя безусловно складывать: измерения запуска сеанса входят
в другие интервалы. Исключительные времена операций суммируются по процессам,
а не являются реальным временем поиска:

| Операция | Время процессов | Доля измеренного времени операций |
| --- | ---: | ---: |
| quantile_extractor_torch | 921,70 с | 71,43% |
| quantile_extractor | 332,21 с | 25,74% |
| wavelet_basis | 26,16 с | 2,03% |
| fourier_basis | 8,93 с | 0,69% |
| ridge | 1,40 с | 0,11% |

Основной первый участок для исправления — статистические признаки, не запуск
Dask и не Ridge. В одной дорогой конфигурации Torch-генератор занимал 52,59
из 58,37 секунды полной оценки. Незавершённые операции могут отсутствовать
в подробной трассировке; приведённые доли относятся только к записанным вызовам.

## Выбранное исправление

Рассмотрены три варианта:

1. Сохранить исходный цикл по окнам: правильный результат, но повторные сортировки
   для четырёх квантилей и множество мелких Python-вызовов.
2. Объединить все окна в одну большую пакетную редукцию: отвергнуто, поскольку
   изменяется округление среднего, стандартного отклонения и квантилей.
3. Ограниченно сортировать окна один раз, сохранив прежние размеры каждой
   численной редукции и интерполяции; выполнить цикл через TorchScript.

Реализован третий вариант в `statistical/window_batch.py`. Квантили сохраняют
ранги и интерполяцию используемой версии PyTorch; форма операндов интерполяции
остаётся `(channels, 1)`. Ориентир реализации: [PyTorch 2.6 Sorting.cpp](https://github.com/pytorch/pytorch/blob/v2.6.0/aten/src/ATen/native/Sorting.cpp).
Среднее и отклонение по-прежнему считаются отдельно для каждого окна, без
перестановки исходных значений. Порядок признаков не меняется.

Компиляция ленивая, один раз в процессе; её стоимость входит в первый вызов.
Размер явно создаваемого отсортированного блока ограничен существующим
`max_elements=262144`. Для float32 значения и int64 индексы сортировки этого
блока занимают до 3 МиБ без учёта внутренних рабочих буферов PyTorch.
Это не ограничение всей памяти процесса.

Для отрицательного нуля оставлен исходный расчёт: выбор одинаковых значений
при сортировке и kthvalue может отличаться знаком нуля. Проверки не ослаблялись.
Для пользовательских методов, конфигураций, неподходящих типов и устройств
также сохраняется исходный путь. CUDA и настройки потоков не менялись.

Пакетная обработка NumPy-входа разрешена и для проверенных оконных режимов.
Глобальные признаки сохраняют прежние группы каналов и формулы. Кэш оценок
кандидатов и переиспользование обученных моделей не добавлялись.

## Проверка результата

На первых восьми наблюдениях внутреннего TRAIN Tecator после Wavelet
полная матрица `(8, 3, 838)` совпала с сохранённым результатом старого кода
по значениям и контрольной сумме. Для 32 наблюдений проверено ещё одно
полное совпадение; медиана трёх повторов преобразования:

| Реализация | Время |
| --- | ---: |
| Исходный расчёт | 2,043 с |
| Ускоренный расчёт | 0,719 с |

Ускорение этого преобразования около 2,84 раза. Это измерение одного режима,
не обещание такого же ускорения любого поиска.

Выбраны только по затратам три уже существовавшие конфигурации: два кандидата,
не успевшие закончить оценку, и самый дорогой завершённый граф. Все параметры
неизменны. Выполнены 18 обучений: три графа × три внутренних разбиения × два
варианта исполнения. Прогнозы исходного и ускоренного вариантов совпали точно.

| Конфигурация | Три разбиения, исходный | Три разбиения, ускоренный |
| --- | ---: | ---: |
| Первый незавершённый кандидат | 26,24 с | 10,53 с |
| Второй незавершённый кандидат | 26,58 с | 10,87 с |
| Самый дорогой завершённый граф | 47,88 с | 19,92 с |

Полная оценка фиксированных графов ускорилась примерно в 2,4–2,5 раза.
Официальный TEST и внешний TRAIN-контроль не загружались. Эти внутренние
метрики не использовались для выбора новых параметров.

Отдельное наблюдение RSS дало около 442,4 МиБ для исходного пути и 452,6 МиБ
для ускоренного. Процесс и распределитель памяти общие, RSS измерен выборочно;
это не доказательство уменьшения памяти. Частый сбор RSS заметно вмешивается
в короткие операции, поэтому задержки взяты из прогона без такого наблюдения.

120 целевых тестов прошли: точное совпадение, знаки нулей, границы временных
блоков, порядок признаков, пользовательские методы, интерфейсы двух задач,
неизменность входов и случайного состояния, прежние оконные режимы и исполнитель.
Первый запуск проверки содержал ошибочное имя тестового файла и не запускал
тесты; его XML сохранён отдельно. Ранние два отказа проверки знака нуля также
сохранены, после исправления пройден полный целевой набор.

## Следующий допуск

Новая заморозка не переиспользует успешные квитанции gate_03 как новый допуск.
Состав тот же: парные B/D на Tecator, ECG200 и Airline, seed42. Порядок явно
задан в `admission.json`: сначала Tecator, чтобы повторно проверить блокирующий
сценарий без двух предварительных длинных поисков. Полная матрица 150 поисков
и её порядок не меняются.

600/90/1200 секунд, минимум 15 поколений, доля отказов до 10%, сетки моделей,
Torch 1/16/False и OKHS-FDMD сохранены. Большая серия разрешена только после
успешных шести проверок. Локальное ускорение не подменяет этот критерий.

Артефакты и исходные численные результаты находятся в
`examples/artifacts/cloud_bundle/bd_tecator_cost_20261105`: `audit_01`,
`probe_before`, `probe_after`, `fixed_replay_01`, `memory_probe_01`,
`window_tests.xml`, `window_tests_fixed.xml`, `final_tests.xml`, `final_tests_02.xml`.
В memory_probe_01 прогнозы не рассчитывались: там выполнены только преобразования
и поле fits равно нулю; сравнение прогнозов относится к fixed_replay_01.
