# Ускорение генераторов и координатора: P0–P3

Параметры моделей, сетки, настройки Torch и пороги EVO-04 не изменяются.
Официальный TEST не используется. Масштабная серия не запускается.

## P0: раздельные измерения

Добавлен явный профилировщик текущего потока с CSV и исходным pstats.
Он не подменяет статистические функции и не отключает ускоренные ветви.
Короткая проверка планирования вызвала обучение ноль раз. Для Tecator проверены
исходный TRAIN и представление wavelet с тремя каналами. Подробный профиль
отделён от чистых измерений времени. Инструкция: `performance_profiling.md`.

## P1: статистические генераторы

NumPy сохраняет прежние построчные и поканальные вызовы, но для проверенного
случая без окна не создаёт отдельный delayed-граф на каждое наблюдение.
Torch расширяет пакетную ветвь на несколько каналов: Hurst вычисляется пакетом,
остальные статистики сохраняют прежнюю группу каналов одного наблюдения.
Пакеты выровнены по целым наблюдениям и ограничены прежними пределами памяти.
Для стандартных функций без дополнительных аргументов исключена повторная
проверка сигнатуры. Пользовательские методы сохраняют прежнюю диспетчеризацию.

Полная векторизация редукций, изменение формул Hurst, объединение реализаций
NumPy/Torch и приближённые признаки не применялись. Разные реализации не обязаны
давать одинаковые признаки друг с другом: сохраняется эталон каждой реализации.

На фиксированном TRAIN Tecator из 137 объектов выполнены прогрев и семь
чередующихся повторов. Измерялось только извлечение признаков, не обучение,
не поиск и не построение wavelet. После каждого вызова проверено точное
численное равенство выходов. Формы, типы и значения входов сохранены.

| Генератор и вход | Эталонная медиана, с | Новая медиана, с | Отношение времени |
| --- | --- | --- | --- |
| NumPy, исходный ряд | 0,86 | 0,64 | 1,33 |
| NumPy, wavelet, три канала | 2,24 | 1,77 | 1,27 |
| Torch, wavelet, три канала | 1,82 | 0,79 | 2,29 |

Артефакты: `examples/artifacts/cloud_bundle/performance_p1/fixed_work_02`.
Эталон — прежний построчный `BaseExtractor`, применявшийся до P1 на этих входах;
для одноканального Torch ранее уже существовало пакетирование, и его ускорение
в таблицу не включено. Фоновая нагрузка не исключена, универсальная оценка
ускорения не заявляется. Исходники проверены на неизменность до и после замера.
`fixed_work_01` не использовать: во время той попытки уточнялись защитные условия
для пользовательских функций; повтор `fixed_work_02` проведён без правок.

## P2: повторные проверки планов

Исходный неизменный граф проверяется один раз на перечисление. Для каждого
предложения сохраняется проверенный исход только на время одной мутации.
При смене объекта исходного графа, ограничений, входного контекста или владельца
плана этот исход неприменим. Публичное применение плана по-прежнему проверяет
подпись источника. Advisor и итоговый runtime-verifier не исключены.

Порядок предложений, лимит 128, распределение действий и потребление RNG
сохранены. Переиспользования оценок моделей между кандидатами нет.

На графе фактического победителя Airline воспроизведены десять мутаций без
обучения; первый повтор — прогрев, девять — измерения с чередованием порядка.
Графы, диагностические решения и конечное состояние RNG совпали с процедурой
повторных проверок из сохранённого исходного кода. Медиана уменьшилась
с 0,0886 до 0,0550 секунды, отношение 1,61. Это время операции мутации,
не доказательство такого же ускорения полного поиска.

Артефакты: `examples/artifacts/cloud_bundle/performance_p2/fixed_work_03`.
Первая попытка только с сохранением допустимых исходов дала отношение 1,03:
такой выигрыш не объявляется надёжным. Основной эффект появился после устранения
повторной проверки источника для каждого предложения. Вторая попытка не запустила
мутации из-за настройки относительного импорта эталонного кода; она сохранена.
