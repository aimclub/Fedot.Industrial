# TSF-05–31: методы и проверка

Изменения дополняют PR #320. Новые составные прогнозы доступны по явным
именам операций и не включены в стандартный набор эволюционного поиска.
Источник внешних бенчмарков и прежние результаты не подменяются.

## Запуск

```bash
python -m examples.release_1_0.tsf_method_study
python -m examples.release_1_0.tsf_method_study --dask
```

Первый запуск печатает RMSE и время каждой модели на трёх временных
отсечениях Airline внутри TRAIN. Последние 12 месяцев исключены до
построения признаков. Для mSSA проверяется одношаговый прогноз на концах
блоков, поэтому его строки нельзя сравнивать с RMSE четырёхшаговой серии.
Второй запуск проверяет совпадение прогнозов в драйвере и на двух
процессных исполнителях Dask с профилем совместимости FEDOT.

Дополнительные проверки печатают JSON. Данные для них не скачиваются
автоматически. Файлы разметки и отчёты не входят в репозиторий.
Прогнозные и панельные сравнения используют формат
`industrial_tsf_comparison@1`. В `provenance` записаны ревизия, признак
изменений отслеживаемых файлов, версии библиотек и контрольные суммы
источников, включая разметку групп. `protocol` фиксирует параметры
разбиения и способ измерения. В результатах остаются индексы записей
или точки отсечения. Отчёт с локальными правками нельзя воспроизвести
по одному хешу коммита.

```bash
python -m examples.release_1_0.tsf_forecast_validation
python -m examples.release_1_0.tsf_panel_validation early ECG200_TRAIN.tsv --with-aeon
python -m examples.release_1_0.tsf_panel_validation early BasicMotions_TRAIN.ts
python -m examples.release_1_0.tsf_panel_validation topology BasicMotions_TRAIN.ts
python -m examples.release_1_0.tsf_panel_validation tser Tecator_TRAIN.ts --with-aeon
python -m examples.release_1_0.tsf_composite_search out/tsf-sequential
python -m examples.release_1_0.tsf_composite_search out/tsf-dask --backend dask
```

- Для дисперсий GARCH установите `arch==7.2.0` и передайте `--with-garch`.
  Модель с нулевым средним не использует положительную волатильность как
  прогноз знаковой детали. ANN использует L-BFGS, а не обучение из статьи.
- Для `--with-aeon` нужны зависимости `fedot-ind[tser]`. Для топологии нужен
  `ripser`. Укажите реальные идентификаторы испытуемых или сеансов через
  `--groups`, чтобы разделить группы и при оценке, и при калибровке. Без
  идентификаторов для BasicMotions проверяется разбиение по записям.
  В наборе `tser` закреплены aeon 0.11.1 и tsfresh 0.20.2:
  эти версии совместимы с ограничением SciPy в FEDOT.
- Для отчёта Dask установите `bokeh>=3.1,<3.5`. Поиск сохраняет историю
  FEDOT, конфигурации и оценки кандидатов, отчёты рабочих процессов и
  прогноз победителя на отложенном участке внутри TRAIN. Выходной каталог
  должен быть новым. Два поколения проверяют исполнение, а не ускорение.
- Отчёты TSER показывают время обучения и предсказания вместе, а память
  измеряется через `tracemalloc`. Это не пиковая память процесса; первый
  вызов может включать компиляцию Numba. Для DrCIF отдельно записан
  повтор с тем же начальным состоянием генератора случайных чисел.

Для дополнительных моделей TSER установите `fedot-ind[tser]` и задайте
`adapter_name` в `ModelSpec`: `freshprince_regressor`, `drcif_regressor`,
`dtw_1nn_regressor` или `rocket_ridge_regressor`. Последний использует
ROCKET, не MiniRocket. Для многоканального входа передайте панель
`(объекты, каналы, время)` или используйте загрузчик .ts с явным числом
каналов. Модели запускаются на тех же разбиениях и с теми же метриками,
что и другие адаптеры `benchmark.industrial.regression`.

## Границы принятия

Фиксированные подграфы представлены одной внешней операцией: их ветви
нельзя разорвать, но сетка поиска может менять параметры отдельных ролей,
например `cnn.width` и `lstm.width`. Page в этой форме принимает один
ряд и прогнозирует ровно один отсчёт. Многоканальный эксперимент
запускает модель напрямую. Если фактический горизонт известен, проверка
графа отклоняет Page с горизонтом больше одного до оценки кандидата.
Явный `forecast_length` должен быть положительным целым и совпадать с
горизонтом задачи. Ariño и Wavelet-HFCM прогнозируют из истории обучения:
при добавлении или исправлении наблюдений нужно заново обучить граф.
MLSTM-FCN принимает панель и использует
фиксированный префикс `prefix.cutoff`, а не решает, когда остановиться.

Эти сравнения не воспроизводят опубликованные числа. Для полной приёмки
остаётся сверка с авторскими реализациями и примерами mSSA, ECTS, EDSC и
Cross-Barcode, исходными рядами Ariño, Jin/Kim и выборками кризисов, а
также проверка WESAD по испытуемым. Поканальный режим шаблонов не
считается реализацией MCFEC без подтверждения правил из полного текста.
