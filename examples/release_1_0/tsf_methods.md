# TSF-05–31: методы и проверка

Изменения дополняют PR #320. Новые составные прогнозы доступны по явным
именам операций и не включены в стандартный набор эволюционного поиска.
Источник внешних бенчмарков и прежние результаты не подменяются.

| Задачи | Точка входа | Граница проверки |
| --- | --- | --- |
| #321–323 | `industrial_forecasting.dwt`, `wavelet_hfcm_forecaster`, `arino_forecaster` | Правый край и связность ветвей, сравнение с базовыми моделями. Для Ariño и Jin/Kim модели ветвей в примере упрощены; это не воспроизведение опубликованных чисел. |
| #324–327 | `neural.wavelet_attention`, `wire`, `neural.coordinate_forecast` | Совместное обучение CNN/LSTM и две формы выхода; позиционный, оконный и амортизированный WIRE. Нужна отдельная оценка обобщения для WIRE на длинном горизонте. |
| #328–329 | `page_models`, `neural.page_projection` | Блочный прогноз, раздельные входы и цели, фиксированная и обучаемая проекции. Тензорный вариант проверяется на восстановлении, не на прогнозе. |

## Запуск

```bash
python -m examples.release_1_0.tsf_method_study
python -m examples.release_1_0.tsf_method_study --dask
```

Первый запуск печатает RMSE и время каждой модели на трёх временных
отсечениях Airline внутри TRAIN. Последние 12 месяцев исключены до
построения признаков. Для mSSA проверяется одношаговый прогноз на концах
блоков, поэтому его строки нельзя сравнивать с RMSE четырёхшаговой серии.
Второй запуск проверяет совпадение прогнозов в драйвере и на двух
процессных исполнителях Dask с профилем совместимости FEDOT.

Для дополнительных моделей TSER установите `fedot-ind[tser]` и задайте
`adapter_name` в `ModelSpec`: `freshprince_regressor`, `drcif_regressor`,
`dtw_1nn_regressor` или `rocket_ridge_regressor`. Последний использует
ROCKET, не MiniRocket. Для многоканального входа передайте панель
`(объекты, каналы, время)` или используйте загрузчик .ts с явным числом
каналов. Модели запускаются на тех же разбиениях и с теми же метриками,
что и другие адаптеры `benchmark.industrial.regression`.

## Границы принятия

Малые численные эталоны и запуск Airline не заменяют парное сравнение
на согласованных наборах. Полное подтверждение исходных настроек
MCFEC, сопоставление с опубликованными таблицами и раздельные измерения
вычислительных затрат остаются самостоятельными проверками.
