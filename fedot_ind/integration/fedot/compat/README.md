# Временная совместимость с FEDOT

Это инструмент разработки для EVO-04, а не автоматическая подмена поведения
библиотеки. Обычный импорт и создание `FedotIndustrial` не применяют исправления.
Каталог рассчитан строго на FEDOT
`d1875e7a1ba49c94d13c51d97ec78829bf459ca8`. Другая версия требует повторного
анализа и обновления манифеста, а не принудительного применения.

## Состав

- `prediction_cache_identity.patch`: передача `descriptive_id` при обучении;
  отсутствие идентификатора отключает обращение к кэшу для этой операции,
  не создавая общего ключа `None`.
- `temporal_evaluation.patch`: разбиение по времени, явная граница прежних
  временных операций и `TensorData`, выход `ridge` в формате `TensorData`,
  передача объявленного `forecast_length` из задачи в расширение и точное
  распознавание преобразований `lagged` / `sparse_lagged` советником.
  Для преобразований с тегом `ts_to_table` добавлена отдельная проверяемая
  граница окон: `TemporalTransformInput` / `TemporalTransformOutput` и
  `transform_temporal`. Она действует только для прогнозирования на исходном
  временном типе и одном одномерном ряде. Обучающие окна, цели и индексы
  передаются вместе; прогнозирование возвращает одно последнее окно без цели.
  Проверка сохранения числа объектов у обычных преобразований не изменена.
- `manifest.json`: исходная версия, контрольные суммы исправлений и получаемых
  файлов, включая тесты для переноса в FEDOT.
- `aligned_feature_fusion.patch`: сохранение порядка одинаковых индексов
  объектов при объединении табличных признаков; повторные индексы отклоняются.
  Это исправление для согласованных ветвей одного источника, а не поддержка
  произвольного объединения разных источников или прогнозов.

Временное разбиение поддерживает подготовленные формы `(series, time)` и
`(series, channels, time)`. Будущий горизонт берётся только из конца истории;
внешняя контрольная цель не попадает в обучающую часть. Прежние временные
операции ограничены одним одномерным рядом. Проверка нескольких блоков
`validation_blocks > 1` отклоняется явно: для неё нужен отдельный последовательный
оценщик. Эти ограничения нельзя обходить изменением формы массива.

## Применение

Создайте отдельную рабочую копию FEDOT на указанном коммите. Не выбирайте
каталог установленного пакета или основную рабочую копию с собственными правками.
Следующие команды используют уже подготовленную локальную копию:

```powershell
# Только проверка применимости, без изменения файлов.
.local/evo02-tests/Scripts/python.exe -m fedot_ind.integration.fedot.compat `
  --worktree .local/worktrees/fedot-evo02-test

# Явное применение к чистой копии.
.local/evo02-tests/Scripts/python.exe -m fedot_ind.integration.fedot.compat `
  --worktree .local/worktrees/fedot-evo02-test --execute

# После применения: проверка версии и контрольных сумм, без повторной записи.
.local/evo02-tests/Scripts/python.exe -m fedot_ind.integration.fedot.compat `
  --worktree .local/worktrees/fedot-evo02-test --audit

$env:PYTHONPATH="$PWD/.local/worktrees/fedot-evo02-test;$PWD"
.local/evo02-tests/Scripts/python.exe -m benchmark.industrial.experiments.mutation_planning.api_runner `
  --output-dir .local/evo04_api_new_run --execute `
  --compatibility-worktree .local/worktrees/fedot-evo02-test
```

При несовпадении версии, контрольной суммы или наличии правок в затрагиваемых
файлах выполнение прекращается. `--compatibility-worktree` в проверке обучения
только проверяет уже применённые исправления, сверяет фактический импорт FEDOT
и записывает сведения в `verification_settings.json`; он ничего не устанавливает.
Для каждого повторного обучения нужен новый каталог результатов.

После расширения исправления для окон прежние проверенные копии FEDOT
не соответствуют обновлённым контрольным суммам. Не применяйте исправление
поверх них: создайте новую чистую копию. Проверенная копия для этого этапа:
`.local/worktrees/fedot-evo04-hankel-smoke`.

Регрессионные проверки Industrial находятся в
`tests/unit/integration/fedot/test_hankel_pipeline.py`: независимый эталон окон
и Ridge, отсутствие зависимости от отложенной цели, настоящие оценки десяти
попыток настройки и владение регистрацией при повторном прогнозировании.
Без явно установленного временного исправления эти проверки отмечают
недоступность нужного протокола; штатный FEDOT пока его не содержит.

## Перенос И Удаление

1. Перенести исправления и вложенные тесты в отдельный PR FEDOT; разделить
   изменение кэша и временного исполнения при необходимости.
2. Проверить существующие тесты FEDOT и полный цикл Industrial с согласованными
   версиями зависимостей. Локальные запуски EVO-04 не заменяют эту проверку.
3. После принятия исправлений обновить закреплённую зависимость Industrial
   и повторить проверку без `--compatibility-worktree`.
4. Удалить этот пакет, его ресурсы, временные параметры проверки и записи
   упаковки только после подтверждения штатного пути. Сохранить исправление
   границы данных Industrial и схему `forecast_length`: это собственные
   обязанности Industrial, а не временная подмена FEDOT.
