# industrial-neural

`fedot_ind.neural` содержит кодировщики, слияние представлений и небольшие
тензорные блоки. Для их импорта и выполнения не нужны FEDOT, GOLEM,
мультимодальные контейнеры Industrial, среда прогнозирования или fastai.
Пакет устанавливается отдельно от Industrial и сохраняет путь импорта
`fedot_ind.neural`. Для обучения нужны только PyTorch и NumPy.

## Ответственность компонентов

| Компонент | Назначение |
|---|---|
| `encoders` | `EncoderConfig`, CNN/MLP, фабрика и стек именованных входов |
| `fusion` | Семь способов слияния именованных представлений и диагностика внимания |
| `blocks` | Функции активации, блок выходного слоя, внимание и маски |
| `device` | Прежняя политика размещения тензоров для совместимости адаптеров |
| `training` | План, цикл обучения с проверкой и контрольные точки |

Ядро не загружает данные, не создаёт клиентов Dask, не меняет настройки Torch
и не определяет разделение TRAIN/TEST. Создание слоёв использует обычную
инициализацию PyTorch; её случайное состояние принадлежит вызывающему коду.

## Именованные тензоры

```python
import torch
from fedot_ind.neural.encoders import EncoderStack, raw_encoder_config, stats_encoder_config
from fedot_ind.neural.fusion import MultiModalGatedFusion

encoders = EncoderStack({
    "sensor": raw_encoder_config(in_channels=2, d_model=16),
    "weather": stats_encoder_config(in_features=5, d_model=16),
})
inputs = {"sensor": torch.randn(4, 2, 32), "weather": torch.randn(4, 5)}
embeddings = encoders(inputs)
fusion = MultiModalGatedFusion(n_inputs=2, d_model=16)
output = fusion.fuse(embeddings, ("sensor", "weather"))
assert output.shape == (4, 16)
```

`EncoderConfig` описывает ранг, число каналов или признаков и размер выходного
представления. Имена входов не привязаны к `raw`, `gaf` или другому перечислению.
В стеке имена должны быть непустыми строками без точки и не повторяться;
порядок конфигураций определяет порядок регистрации слоёв. Размер пакета
может меняться между вызовами. В рамках одного вызова он должен совпадать
у всех используемых входов. Отсутствующий вход не заменяется нулями.

Слияние принимает отображение имён в тензоры `(B, D)` и отдельный порядок
входов. В остаточных вариантах прежний аргумент `raw_modality` означает имя
основного входа; наличие доменного перечисления не требуется.

CNN/MLP не интерпретируют маски переменной длины. В слоях внимания доступны
прежние `attn_mask` и `key_padding_mask`: булево `True` закрывает позицию,
вещественная маска добавляется к оценкам до softmax. Полностью закрытые строки
не становятся нулевым выходом: прежнее поведение softmax с NaN не изменено.

## Совместимость

Имена модулей, слоёв и ключи `state_dict` не меняются. Industrial использует
это же ядро: адаптеры FEDOT, мультимодальные контейнеры и прикладные модели
остаются в Industrial. У `FutureClassifierTrainer.save_checkpoint` прежнее
назначение: сохранить лучшую модель для предсказаний, а не продолжить обучение.

## Установка без FEDOT

Нужен Python 3.10 или 3.11. В новом виртуальном окружении из корня репозитория:

```bash
python -m pip install --index-url https://download.pytorch.org/whl/cpu "torch==2.6.0"
python -m pip install ./packages/industrial-neural
python -m pip check
python -I examples/neural/cpu_resume.py --standalone
```

Вместо исходников можно установить wheel из вложения `industrial-neural-distributions`
задания сборки. Чтобы собрать его локально, установите `build` и выполните
`python -m build packages/industrial-neural --outdir dist/neural`.
Выпуск на PyPI не входит в этот этап.

## Обучение и восстановление

`TrainingPlan` задаёт число эпох и необязательную раннюю остановку.
`TrainingSession` принимает уже созданные модель, оптимизатор, функцию потерь
и загрузчики. По умолчанию ожидаются пары `(вход, цель)`; для других
форматов передайте `batch_adapter`, который возвращает `SupervisedBatch`.
Загрузчики должны допускать повторный обход. Потери должны быть скалярами,
усреднёнными по объектам. Если передан проверочный набор, лучшая эпоха
выбирается по его потерям, иначе по потерям обучения.

`run(until_epoch=2)` завершает вторую эпоху; бюджет всего запуска при этом
не меняется. `save_checkpoint(path)` сохраняет веса **последней** эпохи,
лучшие веса, оптимизатор, историю и состояния генераторов Python, NumPy
(глобальный MT19937), Torch CPU и загрузчиков. Файл записывается с заменой
после успешной записи временного файла. `load_checkpoint(path)` принимает
только контрольные точки текущей схемы и восстанавливает состояние в новой
сессии, включая глобальные генераторы. `best_weights()` возвращает копию
для предсказаний и не меняет состояние обучения.

Для точного возобновления нужны те же данные, модель, оптимизатор, функция
потерь без изменяемого состояния, настройки и версии зависимостей. Формат
поддерживает CPU, границы эпох и стандартный `DataLoader` с
`num_workers=0`, обычным последовательным или случайным выбором объектов
и автоматическим формированием пакетов. Пользовательские источники
случайности, например отдельный `numpy.random.Generator` внутри набора,
в файл не входят. Нет гарантий для CUDA, распределённого обучения,
планировщиков скорости обучения или возобновления внутри эпохи.
Загрузка использует `weights_only=True`; используйте файлы из доверенного
источника.

[Исполняемый пример](../../examples/neural/cpu_resume.py) сравнивает
непрерывный запуск с восстановлением после второй эпохи в новом процессе.
Он проверяет точное совпадение потерь, весов, оптимизатора и генераторов для
классификации с CNN и прогноза на три шага вперёд. Данные синтетические,
загрузки из сети нет. Для ручного запуска двух частей:

```bash
python -I examples/neural/cpu_resume.py --task forecasting --until-epoch 2 --save paused.pt
python -I examples/neural/cpu_resume.py --task forecasting --resume paused.pt --save finished.pt
```
